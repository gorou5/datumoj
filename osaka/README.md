# 一瞬间 ISSHUNKAN — osaka.datumoj.com (Sample v0.2)

独立项目的样本版：把一个 150 人社群里碎片式的聊天、代码协作与 Agent 协作发言，结构化成以「瞬间」为最小单位的知识发现站。本项目独立运作，样本内容为完全独立的虚构社群（大阪，各行各业的 132 人 + 18 个 Agent），不取自也不关联任何其他项目。

- 本地源：`dist/index.html`（单文件静态页，零框架、零构建）
- 部署：Cloudflare Pages 项目 `datumoj-osaka`（Direct Upload），自定义域名 osaka.datumoj.com
- 入仓：gorou5/datumoj 仓库 `osaka/` 目录仅作源码存放（独立目录，不与其他目录互链、不进导航与动态）
- 视觉：护眼浅色（米纸底、墨绿灰字、低饱和点缀）＋留白版式（v0.2 按用户反馈改版；v0.1 深色版备份在 src/）

## 信息架构
一级单位：瞬间 Moment / 脉络 Constellation / 未决 Loop / 产物 Artifact / 成员 Member。
展示原则：不按时间排、按想法的一生排（诞生→共鸣→生长→悬置）；可缩放（一句话→摘要→原始碎片）；每条提炼必带出处、原话不改写。

## 信息来源接入顺序（定版草案，详见站内「接入顺序」页）
1. 代码协作（出处满分、产物闭环先跑通）
2. Agent 协作记录（最易失、先救这一类；零额外授权）
3. 打捞层：成员自愿投稿＋被引用/被写进回顾的话（先立习惯、授权最轻）
4. 即时通讯全量流（最后；前置条件：知情同意规矩＋脱敏/可撤回＋平台先定）
边界：一对一私聊永不接入；线下只收自愿回顾。

## 框架调研结论（2026-10-28）
无现成框架直接做「一瞬间发现」。最接近：Beever Atlas（聊天→原子事实→Wiki+图谱+MCP，提炼层）、Linen / Answer Overflow（聊天存档搜索）、Discourse（结构化论坛，但需讨论搬家）、Quartz（数字花园发布与图视图）、Polis / Kialo（立场组织）、Tilda（学术原型，三层缩放思想来源）。建议组合：Beever 式提炼 + Quartz 式发布 + 自研展示层。先验证展示，再接管线。
