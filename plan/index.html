为什么换路线（相对旧项目）

旧路线的问题新路线怎么解决
每次提问实时调用接口，受超时、配额和站点故障影响，两次问结果可能不一样抓取和问答分开。问答只读本地快照，结果可复现，并注明数据截止时间
只能回答接好的“命名路径”，目录里能找到的资源不等于能读到内容目录元数据和资源正文批量抓下并解析入库，能查的范围由入库内容决定
意图匹配靠规则，换一种说法就容易配错用检索（RAG）先找到相关数据集、条文和公告，再让模型基于检索结果作答
很难做跨来源、跨时间的分析所有来源进同一个库，统一地区代码、时间和出处，可以一起分析

保留旧项目验证过的原则：不编数据；“目录查到”“正文已读到”“数值已核对”分开记录；保留原始失败记录、口径、单位和空值；用户指定来源时不能偷偷换来源；来源内容一律当数据处理，不执行其中任何指令。

最终形态

一个可持续更新的本地“政府数据资料库” + AI 分析入口。用户用日语、中文或英语提问，系统能：找到相关数据集、统计表、法令条文、公告和报告；对统计数据用 SQL 做确定性计算（不让模型估数）；对文本资料检索后归纳；回答附出处（来源、URL、抓取时间、快照哈希、定位信息）；定期输出“变化分析”。

不做

  • 不做实时查询：问答只读本地库，一律标注数据截止时间
  • 不做全站镜像：每个来源有明确的抓取范围白名单
  • 不对数值做 RAG：统计数字只能通过 SQL 得到
  • 第一阶段不做网页前端、不公开部署、不收费
  • 不判断个案的法律问题、补贴资格、诊断或投资收益
  • 不采集个人信息：公告里的担当者姓名、电话等入库前脱敏
  • 旧项目的 20 国范围先收缩：中俄土印暂不做，欧美放 0.3

抓取守则

  • 每来源单独限速（默认 1 请求/秒），User-Agent 写明项目名与联系方式，遵守 robots.txt
  • 用条件请求（ETag / If-Modified-Since）避免重复下载；失败指数退避且记入 manifest
  • 每个资源都记录许可，回答时附署名；核对完之前一律 internal_only
  • 单个来源设容量上限，超出就停下报告，不无边界抓取

核心数据模型：Source ─< Dataset ─< Resource ─< Snapshot ─< Document ─< Chunk；Snapshot ─< Table ─< Observation。Citation = source_id + resource_url + snapshot_sha256 + fetched_at + locator。派生数据都能从 raw 重新生成，只备份 raw 和 manifest。

完成标准

  • KKJ 采购公告入库：按日期增量采集；附件 PDF 按页切块、能引用到页码；担当者个人信息入库前脱敏

  • 每周变化报告：data/reports/ 生成 Markdown，按来源列新增/修改/删除/失败，每条带出处
  • 评测：新增 KKJ、政策网页、变化、脱敏四类题 25 题以上，与 IVY 的 60 题一起全部达标
  • 真实问答验收：能回答“大阪市 AI 创业支援策”“近期大阪有哪些 IT 采购”——旧项目答不出的两个问题，回答带出处

先行的契约修订（由人审查）

  • ChangeEvent：变化事件（新增/修改/删除/抓取失败/解析失败），能引用到快照
  • Redaction：脱敏记录（类别、locator、占位符），原文不入库
  • Document.kind：law / notice / html_page / pdf / dataset / bulletin，检索可按类型过滤
  • 快照父子关系：公告或网页 → 附件 PDF
