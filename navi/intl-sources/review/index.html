P2-1 — Scan result is broader than the documented scan scope

Evidence: inputs/index.html:768-769; inputs/ONE_PAGE.md:40.

The page labels the result as a sensitive-information scan with zero hits. The source names only email, phone, key, and local-path scans. With the broad label, a reader can infer that all sensitive-data categories were scanned. The failing scenario is a reader relying on this page as evidence that unlisted categories were checked. P2-2 — Reduced-motion scene does not update when IntersectionObserver is unavailable

Evidence: inputs/index.html:1096-1109, inputs/index.html:1010-1016, and inputs/index.html:1142-1143.

observeSections returns when IntersectionObserver is absent. In reduced-motion mode the animation loop is not started, and the scroll handler updates progress and the chapter label without calling drawStatic. In the Node stub, scrolling to the final chapter changed activeIndex to 7 while the canvas paint count stayed at 10,000. The failing scenario is a browser without IntersectionObserver and with reduced motion enabled: the decorative particle scene remains on the initial chapter while the reader scrolls.

P2-3 — Light preference is skipped if Canvas context creation fails

Evidence: inputs/index.html:793-797 and inputs/index.html:1134.

The early return for a null Canvas context runs before the code applies the light-scheme class. The Node stub confirmed that a light system preference leaves theme-light unset when Canvas is unavailable. The failing scenario is a light-scheme reader whose browser cannot create a 2D context: the readable page remains in the dark palette instead of using its light tokens. Apply the theme before the Canvas early return or provide a CSS preference fallback.
