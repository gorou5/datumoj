# 数据源与连接器规范

## 1. 术语区分（不要混用）

| 概念 | 含义 | 举例 |
|---|---|---|
| 政府机构 | 数据的发布方 | 日本国税厅 |
| 数据集 | 机构发布的数据集合 | 法人番号公表サイト |
| API 接口 | 机器可调用的访问点 | EDINET API v2 |
| 文件 | 可下载的数据文件 | 某 CSV 全量下载 |
| 数据源连接器 | 本项目中连接上述内容的模块 | `jp-nta-houjin-bangou` |
| 采集任务 | 一次具体的抓取/同步执行 | 每日增量同步任务 |
| 查询结果 | 某次调用返回的数据 | 附带证据链的结果对象 |

## 2. 数据源描述

每个数据源用 `schemas/registry/data-source.schema.json` 描述，机器可读 JSON 放在
`catalog/`（待第一个真实数据源落地时创建）或模块自带目录。
真实示例：`examples/data-sources/jp-nta-houjin-bangou.json`。

必填：`id`、`name`、`country_region`、`publisher`、`official_url`、`access_method`。
其余按 §3 的清单尽量填全；**不能确认填 `"unknown"`，不得编造**。

## 3. 建档清单（接入新数据源时逐项确认）

- 数据是否**直接查询**，还是需要缓存/保存原始文件（及原因）；
- 是否允许再分发；是否要求署名来源；
- 访问频率限制、认证要求；
- 数据更新机制、失效与删除机制；
- 使用许可（名称 + 链接）；`last_verified`（最后验证时间）。

## 4. 连接器实现建议

- 一个连接器只连**一个**官方来源；多来源组合在上层工作流里做。
- 输出统一携带证据链（见 `docs/interoperability.md` §3）。
- 错误要区分：来源不可用 / 频率受限 / 认证失败 / 数据格式变化 —
  调用方据此决定重试、退避或告警；**来源不可用时给明确错误，不许用
  未经验证的替代数据冒充**。
- 测试用录制/模拟的 HTTP 响应（fixtures），不许在 CI 里高频打真实政府网站。

## 5. 目录约定（首个模块落地时启用）

```
catalog/                        # 数据源描述 JSON（机器可读目录）
connectors/<country>/<agency>/  # 如 connectors/jp/nta/
```

每个连接器目录内：`README.md`（人类文档）+ 描述 JSON + 实现 + `fixtures/` 测试夹具。
