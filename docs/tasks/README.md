# 任务文件（审核用副本）

这里是 0.1 版本（代号 IVY）的 32 个任务文件，编号 `DATUMOJ-IVY-<序号>`（编号按开发线分号段，见 `docs/TASKS.md`），提交到 git 是为了方便团队审核。

- **调度器不读这个目录。** 它只读 `.orch/tasks/`，那个目录在 `.gitignore` 里，不进 git。
- **审核期间以这里为准**：意见直接在 PR 里提，或者改这里的文件。
- **审核通过后**，主对话把这里的文件复制到 `.orch/tasks/`，然后运行 `bin/orch validate .orch/tasks` 和 `bin/orch sync`。
- **调度器开始执行后**，任务状态由调度器维护。要调整还没开始的任务，就同时改这里和 `.orch/tasks/` 两份，保持一致；已完成的任务不改，另开新任务。

格式说明见调度器文档 `docs/formats.md` 第 1 节。任务总表和执行顺序见 `docs/TASKS.md`。

审核时建议重点看这几处：
1. 每个任务的“要求”能不能被测试或审查逐条核对；
2. `scope` 是否够窄，会不会让两个任务改同一个文件；
3. 依赖顺序（`depends_on`）是否合理；
4. 哪些任务需要人审查（`review.by: human`），目前有 001、002、303、603、702、703、704、901、902、903；
5. 契约（001、002）是并行开发的基础，**每条线的负责人都要看**。
