# 目标
每个来源一个 `sources/<id>.yaml`，程序启动时能校验并加载，抓取范围、限速、许可都从这里读。

# 背景
PLAN 第 5 节。注册表决定“抓什么、抓多少、多快”，是防止无边界抓取的第一道闸。

计划见 `docs/PLAN.md`，任务总表见 `docs/TASKS.md`。
- 测试全部离线：不访问网络，HTTP 一律用 `tests/fixtures/` 里的录制样本或本地假服务器。
- 依赖已锁定在 `uv.lock`，不能新增依赖，也不能改 `pyproject.toml`。确实需要新依赖时，写进 `results/IVY-004/summary.md` 并停下来问。
- `tests/fixtures/` 下已有的样本只读；需要新样本就新建文件，并在该目录的 README.md 旁另写说明文件。
- 代码注释、docstring 用中文或英文均可；标识符用英文。

# 要求
1. pydantic 模型 `SourceSpec`：`id`（`^[a-z]{2,4}(-[a-z0-9]+)+$`）、`name`、`country`、`kind`（`egov_law`、`ckan`、`stat_dashboard`、`estat_files`、`jma_feed`、`kkj`、`web_seed` 等）、`base_url`、`allowed_hosts`、`rate_per_sec`、`max_total_bytes`、`max_files`、`schedule`（cron 字符串或 `manual`）、`license_default`、`attribution`、`scope`（按 kind 不同的白名单配置，自由 dict 但必须非空）、`needs_key`（布尔，Key 名只写环境变量名，不能写值）、`retention_note`。
2. `load_registry(dir)` 加载全部 yaml，id 与文件名必须一致、不能重复；校验失败的报错要指出文件和字段。
3. 检测 yaml 里疑似写了明文 Key（字段名含 key/token/secret 且值不是 `env:` 开头）时报错。
4. 写好 `sources/jp-egov-law.yaml`（e-Gov 法令 API v2，限速 1/秒，许可写“政府標準利用規約 / 公共データ利用規約 第1.0版”待核实）。
5. `sources/_schema.md` 用中文写清每个字段的含义和示例。
6. 测试覆盖：合法加载、id 与文件名不符、重复 id、缺字段、明文 Key、scope 为空。

# 不做
- 不写其他来源的 yaml（各采集器任务自己加）。
