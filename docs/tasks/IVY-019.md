# 目标
统计 Dashboard 的指标目录和精选指标的全地区时间序列能抓下来并转成 Observation。

# 背景
Dashboard API 无需 Key；`getData` 每次最多 5 个指标、50 个地区，**没有分页**；`modifiedFrom` 可做增量。样本在 `tests/fixtures/stat_dashboard/`（来自旧项目的 `dashboard-metadata-public.json`、`dashboard-population-public.json` 等）。

计划见 `docs/PLAN.md`，任务总表见 `docs/TASKS.md`。
- 测试全部离线：不访问网络，HTTP 一律用 `tests/fixtures/` 里的录制样本或本地假服务器。
- 依赖已锁定在 `uv.lock`，不能新增依赖，也不能改 `pyproject.toml`。确实需要新依赖时，写进 `results/IVY-019/summary.md` 并停下来问。
- `tests/fixtures/` 下已有的样本只读；需要新样本就新建文件，并在该目录的 README.md 旁另写说明文件。
- 代码注释、docstring 用中文或英文均可；标识符用英文。

# 要求
1. 指标目录全量抓取，每个指标作为一条 Dataset 存进 IVY-015 的目录存储，这样 `search_catalog` 能搜到指标。
2. 精选指标清单写在 `sources/jp-stat-dashboard.yaml` 的 `scope.indicators`（先放人口、世帯数、出生、死亡、転入転出、県内総生産、就業者数等 10 个左右，指标码从样本里取）。
3. 分批规划器：把“指标 × 地区（47 都道府县 + 全国）”拆成每批 ≤5 指标、≤50 地区的请求，纯函数，单独测试。
4. 转换：响应 → Observation，地区码用 IVY-017 归一化，时间解析成 `time_start/time_end/granularity`，单位原样保留。
5. 增量：用 `modifiedFrom` 只取上次以后更新的指标。
6. 测试：规划器边界（正好 5/50、超出、空）、转换后的数值和样本逐条一致、地区码正确、增量参数正确。
