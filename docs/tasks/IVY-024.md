# 目标
检索同时用关键词和向量，结果用 RRF 融合；查不到时能准确说明是哪种缺口。

# 背景
PLAN 4.3 第 5–7 条。旧项目把“零命中”“没入库”“抓取失败”“超出范围”混在一起，用户分不清。

计划见 `docs/PLAN.md`，任务总表见 `docs/TASKS.md`。
- 测试全部离线：不访问网络，HTTP 一律用 `tests/fixtures/` 里的录制样本或本地假服务器。
- 依赖已锁定在 `uv.lock`，不能新增依赖，也不能改 `pyproject.toml`。确实需要新依赖时，写进 `results/IVY-024/summary.md` 并停下来问。
- `tests/fixtures/` 下已有的样本只读；需要新样本就新建文件，并在该目录的 README.md 旁另写说明文件。
- 代码注释、docstring 用中文或英文均可；标识符用英文。

# 要求
1. `hybrid_search(queries: list[str], k, source_ids=None, date_range=None)`：多个查询（多查询检索）分别跑 FTS 和向量，用 RRF（k=60，可配置）融合、按 `chunk_id` 去重；每条结果记录是被哪个查询、哪种检索命中的。
2. 向量索引不可用（没建或模型不在）时退回纯关键词，并在结果里标注 `degraded=true`。
3. `coverage.py`：`gap_state(source_ids, hits)` 返回 `ok`/`zero_hits`/`not_ingested`（注册表有但没有成功快照）/`fetch_failed`（最近一次抓取失败，附原因）/`out_of_scope`（注册表里没有这个来源）；同时给出“最近的可查内容”（例如该来源已入库的最新快照时间）。
4. `freshness(source_id)`：最后成功抓取时间、快照数。
5. 测试：融合排序（人工构造两路结果验证 RRF 计算）、去重、降级、四种缺口状态各至少两个用例。
