# 目标
有一套离线评测：读题库 yaml，对检索函数跑一遍，算出 Recall@k、MRR，并输出报告。

# 背景
PLAN 第 10 节。端到端的 LLM 评测不在这里做，这里只评测确定性的部分（检索、SQL 数值、缺口状态、引用可还原）。

计划见 `docs/PLAN.md`，任务总表见 `docs/TASKS.md`。
- 测试全部离线：不访问网络，HTTP 一律用 `tests/fixtures/` 里的录制样本或本地假服务器。
- 依赖已锁定在 `uv.lock`，不能新增依赖，也不能改 `pyproject.toml`。确实需要新依赖时，写进 `results/IVY-012/summary.md` 并停下来问。
- `tests/fixtures/` 下已有的样本只读；需要新样本就新建文件，并在该目录的 README.md 旁另写说明文件。
- 代码注释、docstring 用中文或英文均可；标识符用英文。

# 要求
1. 题库格式（写进 `eval/README.md`）：`id`、`question`、`lang`（ja/zh/en）、`kind`（`retrieval`/`numeric`/`gap`/`time`/`injection`）、`queries`（可选：预先改写好的日文查询列表，模拟宿主模型的查询改写）、`expect.hits`（`doc_key` + 可选 locator 前缀）、`expect.value`（`sql` + `equals` + 容差）、`expect.gap_state`、`must_not`、`notes`。
2. `load_questions(dir)` 校验格式，报错指出文件和题号。
3. `run_eval(questions, retriever, k=10)`：retriever 是可注入的函数；对 `retrieval` 类题算 Recall@k（命中任一期望即算召回）、MRR；其他类题本任务先跳过并计数，后续任务（IVY-029）补上。
4. 输出 Markdown 和 JSON 报告：总体指标、按来源和语言分组、失败题列表（附检索到的前 3 条）。
5. `check_gate(report, thresholds)` 返回是否达标，供以后作为合并门槛。
6. 测试用小型假检索器和 5 道假题覆盖指标计算（含边界：无期望、全部命中、全不命中）。
