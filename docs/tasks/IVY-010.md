# 目标
从 manifest 里找出还没解析的快照，交给对应的解析器，结果写进 chunk 存储和索引；重复运行不会重复处理。

# 背景
连接 IVY-007（raw）、IVY-008（解析器）、IVY-009（存储与索引）。

计划见 `docs/PLAN.md`，任务总表见 `docs/TASKS.md`。
- 测试全部离线：不访问网络，HTTP 一律用 `tests/fixtures/` 里的录制样本或本地假服务器。
- 依赖已锁定在 `uv.lock`，不能新增依赖，也不能改 `pyproject.toml`。确实需要新依赖时，写进 `results/IVY-010/summary.md` 并停下来问。
- `tests/fixtures/` 下已有的样本只读；需要新样本就新建文件，并在该目录的 README.md 旁另写说明文件。
- 代码注释、docstring 用中文或英文均可；标识符用英文。

# 要求
1. 解析器注册表放在 `src/datumoj/parsers/registry.py`：`PARSERS` 按来源 kind 和 content_type 选解析器，提供 `register_parser(kind, content_type, fn, version)`；法令走 `extract_law_xml` + `xml_law`。以后的解析任务只改这个文件来登记。
2. `parse_pending(source_id=None)`：只处理新快照（按 sha256 判断，已解析的记在 SQLite 表 `parsed(sha256, parser, version, status, error)`）；解析器版本变了才重解析。
3. 解析失败记录原因并继续处理其他快照，最后汇总。
4. `reindex(source_id=None)` 可以全量重建 FTS。
5. 测试：用 fixture 构造 raw+manifest（直接调用 IVY-002/001 的接口写入），跑两遍确认第二遍什么都不做；一个坏 XML 不影响其他。
