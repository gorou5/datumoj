# 目标
所有采集器共用一套执行流程：先列出要抓的资源，再逐个礼貌抓取，存进 raw 并写 manifest，失败也有记录。

# 背景
后面的法令、CKAN、Dashboard、e-Stat、JMA、KKJ 采集器都继承它。

计划见 `docs/PLAN.md`，任务总表见 `docs/TASKS.md`。
- 测试全部离线：不访问网络，HTTP 一律用 `tests/fixtures/` 里的录制样本或本地假服务器。
- 依赖已锁定在 `uv.lock`，不能新增依赖，也不能改 `pyproject.toml`。确实需要新依赖时，写进 `results/IVY-006/summary.md` 并停下来问。
- `tests/fixtures/` 下已有的样本只读；需要新样本就新建文件，并在该目录的 README.md 旁另写说明文件。
- 代码注释、docstring 用中文或英文均可；标识符用英文。

# 要求
1. 抽象类 `Crawler`：子类实现 `plan(spec, state) -> Iterable[FetchJob]`（可以是生成器，支持分页时边抓边产出新任务）和可选的 `after_fetch(job, result) -> Iterable[FetchJob]`。
2. `run(spec, limit=None, dry_run=False)`：按注册表的限速、`max_files`、`max_total_bytes` 执行；超过上限就停下并在结果里报告“因上限停止”，不能悄悄截断。
3. 每次抓取：用 IVY-003 客户端发条件请求（从 manifest 取上次的 etag/last_modified），成功的内容写 raw，结果写 manifest；304 也记录。
4. 识别“200 但内容是 SPA 外壳或空正文”（可由子类提供判断函数，基类提供一个默认判断：HTML 正文去标签后少于 N 个字且含 `<div id="root">`/`__next` 等），记为 `spa_shell`/`empty_body`。
5. 返回 `CrawlReport`：新增、未变化、失败（按原因计数）、停止原因、用时。
6. `dry_run` 只列出计划，不发请求。
7. 注册表 `CRAWLERS: dict[kind, type[Crawler]]` 放在 `crawlers/__init__.py`。
8. 测试用一个假子类和 `ReplayTransport` 覆盖：正常、304、失败落库、上限停止、dry_run、SPA 外壳识别。
