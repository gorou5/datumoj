# 目标
一部法令的 XML 能变成一个 Document 和按“条”切分的 Chunk 列表，每块都能定位到第几条第几项。

# 背景
法令标准 XML 的元素：`Law`/`LawNum`/`LawBody`/`LawTitle`/`Part`/`Chapter`/`Section`/`Subsection`/`Division`/`Article`/`ArticleCaption`/`ArticleTitle`/`Paragraph`/`ParagraphNum`/`Item`/`Subitem1..`/`SupplProvision`/`AppdxTable` 等。样本在 `tests/fixtures/egov_law/`。

计划见 `docs/PLAN.md`，任务总表见 `docs/TASKS.md`。
- 测试全部离线：不访问网络，HTTP 一律用 `tests/fixtures/` 里的录制样本或本地假服务器。
- 依赖已锁定在 `uv.lock`，不能新增依赖，也不能改 `pyproject.toml`。确实需要新依赖时，写进 `results/IVY-008/summary.md` 并停下来问。
- `tests/fixtures/` 下已有的样本只读；需要新样本就新建文件，并在该目录的 README.md 旁另写说明文件。
- 代码注释、docstring 用中文或英文均可；标识符用英文。

# 要求
1. 用 lxml 安全解析：`resolve_entities=False`、`no_network=True`、禁用 DTD 加载、限制输入大小（参考旧项目 `secure-xml.ts`）。
2. 每条（Article）一个 Chunk：`title_path` 含法令名和编/章/节/条标题；`locator` 形如 `art=27`；条文过长（>2000 字）时按项再切，locator 为 `art=27;para=2`。
3. 附则（SupplProvision）的条：locator 前加 `suppl=<修正法令番号或 0>`；别表：`table=<序号>`。
4. 条号用 IVY-005 的 `kansuji_to_int` 转成数字；“第二十七条の二”记为 `art=27_2`。
5. Chunk 文本是可读的纯文本：条标题 + 条文，项号、号号保留原样。
6. Document 记录法令番号、法令名、施行日（如果 XML 里有）、法令 ID（作为 `doc_key` 的一部分：`jp-egov-law:<法令ID>`）。
7. 测试覆盖：个人信息保护法这类带章节的法令、带“条の二”的条、附则、别表、含实体声明的恶意 XML 被拒绝。
