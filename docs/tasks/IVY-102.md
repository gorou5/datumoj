# 目标
每一次抓取（包括失败的）都记录在 SQLite 里，能查到最近一次结果、失败汇总和新鲜度。

# 背景
开发线：A 抓取基础。旧项目的原则：失败要原样保留。缺口状态（`not_ingested`、`fetch_failed`）就靠这里判断。

计划见 `docs/PLAN.md`，任务总表、开发线和跨任务约定见 `docs/TASKS.md`。
- **只依赖契约**：数据模型在 `src/datumoj/core/models.py`，接口协议和插件发现在 `src/datumoj/core/contracts.py`，假实现和契约测试在 `src/datumoj/testing/`。不要 import 其他开发线的实现模块（集成任务除外）。
- 测试全部离线：不访问网络，HTTP 一律用 `tests/fixtures/` 里的录制样本或本地假服务器。
- 依赖已锁定在 `uv.lock`，不能新增依赖，也不能改 `pyproject.toml`。确实需要时写进 `results/IVY-102/summary.md` 并停下来问。
- `tests/fixtures/` 下已有的样本只读；需要新样本就新建文件。
- 需要改契约（models.py、contracts.py）时不要自己改，写进 summary 并停下来问。

# 要求
1. 实现 `Manifest` 协议：`record_snapshot`、`latest_snapshot(resource_url)`、`last_success`、`snapshots_for(source_id)`、`failure_summary(source_id)`、`freshness(source_id)`，以及解析状态表 `parsed(sha256, parser, version, status, error)` 的读写。
2. 写入在事务里完成；同一个 `snapshot_id` 重复写入报错。
3. 有 schema 版本表，版本不符时报清楚的错误。
4. 继承 `ManifestSuite` 跑通合格测试，再补失败记录、并发写入（两个连接）、版本不符的测试。
