# 目标
能把 e-Gov 法令 API v2 的法令列表和每部法令的现行版 XML 抓进 raw，支持 LIMIT 和增量。

# 背景
接口说明在交接资料 `/Users/aaron/codex_workspace/digital-assets/analysis/eGov_Law_API_v2_Agent_Guide.md`（可读，不要复制大段）。录制样本在 `tests/fixtures/egov_law/`，文件说明见同目录 README.md。

计划见 `docs/PLAN.md`，任务总表见 `docs/TASKS.md`。
- 测试全部离线：不访问网络，HTTP 一律用 `tests/fixtures/` 里的录制样本或本地假服务器。
- 依赖已锁定在 `uv.lock`，不能新增依赖，也不能改 `pyproject.toml`。确实需要新依赖时，写进 `results/IVY-007/summary.md` 并停下来问。
- `tests/fixtures/` 下已有的样本只读；需要新样本就新建文件，并在该目录的 README.md 旁另写说明文件。
- 代码注释、docstring 用中文或英文均可；标识符用英文。

# 要求
1. `plan`：先抓法令列表（按 API 的分页参数逐页），再为每部法令生成“现行版全文（XML 格式）”的抓取任务。
2. 法令正文在 JSON 里以 base64 编码的 XML 提供：采集器只负责把原始响应存进 raw；另外提供纯函数 `extract_law_xml(raw_json_bytes) -> bytes` 供解析器使用，解码失败要报清楚的错误。
3. 增量：从列表里读每部法令的修订信息（修订 ID 或施行日），和 manifest 里上次抓到的对比，没变的不再抓正文。
4. `limit` 限制法令部数（M0 验收用 `LIMIT=20`）。
5. 在 `CRAWLERS` 注册 `egov_law`。
6. 测试用回放样本覆盖：分页、正文抓取、增量跳过、某一部法令 404 时继续抓其他的并记录失败、`extract_law_xml` 的正常和损坏输入。
