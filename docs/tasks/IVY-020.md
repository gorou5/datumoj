# 目标
精选的 e-Stat 统计表文件（CSV/XLSX）能按清单下载，并把至少两种常见版式转成 Observation。

# 背景
旧项目实际能用的是文件下载路径（按 statInfId 下载）。e-Stat 文件多为 cp932，响应头不可信。精选清单的初版见 `docs/TASKS.md` 的“e-Stat 第一批主题”。样本在 `tests/fixtures/estat_files/`。

计划见 `docs/PLAN.md`，任务总表见 `docs/TASKS.md`。
- 测试全部离线：不访问网络，HTTP 一律用 `tests/fixtures/` 里的录制样本或本地假服务器。
- 依赖已锁定在 `uv.lock`，不能新增依赖，也不能改 `pyproject.toml`。确实需要新依赖时，写进 `results/IVY-020/summary.md` 并停下来问。
- `tests/fixtures/` 下已有的样本只读；需要新样本就新建文件，并在该目录的 README.md 旁另写说明文件。
- 代码注释、docstring 用中文或英文均可；标识符用英文。

# 要求
1. 清单写在 `sources/jp-estat-files.yaml` 的 `scope.tables`：每项含 `stat_inf_id`、`survey`、`title`、`layout`（版式名）、`expected_area_level`。
2. 下载后核对：文件里的表题、调查名、地区是否和清单一致，不一致记为失败（旧项目踩过“下载 ID 实际属于别的县”）。
3. 版式转换器至少两种：`wide_area_by_year`（行是地区、列是年份）和 `long_with_dims`（每行一个维度组合）。转换器只认清单指定的版式，认不出就报错，不猜。
4. 表头、注记、单位行用 IVY-016 的工具识别；注记（“-”“…”“x”）存进 `note`，`value` 为空。
5. `survey` 必须填写，不同调查的数据不能混进同一张 Observation 表。
6. 测试：两种版式各至少一个真实样本，逐个核对 10 个以上数值；地区不符时报失败；未知版式报错。

# 不做
- 不用 e-Stat API（需要 appId，放在 P2）。
