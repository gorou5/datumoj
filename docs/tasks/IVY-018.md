# 目标
所有统计数值都存成统一的 Observation（带单位、口径、调查名、地区码、时间和出处），可以用 SQL 只读查询并拿到每行的出处。

# 背景
PLAN 4.1 和第 4.3 节第 2 条：数值只能来自 SQL。PLAN 第 12 节：不同调查的数据不能相加或算增长率。

计划见 `docs/PLAN.md`，任务总表见 `docs/TASKS.md`。
- 测试全部离线：不访问网络，HTTP 一律用 `tests/fixtures/` 里的录制样本或本地假服务器。
- 依赖已锁定在 `uv.lock`，不能新增依赖，也不能改 `pyproject.toml`。确实需要新依赖时，写进 `results/IVY-018/summary.md` 并停下来问。
- `tests/fixtures/` 下已有的样本只读；需要新样本就新建文件，并在该目录的 README.md 旁另写说明文件。
- 代码注释、docstring 用中文或英文均可；标识符用英文。

# 要求
1. Observation 字段：`obs_id`、`source_id`、`dataset_key`、`table_key`、`survey`（调查名）、`indicator`（指标名）、`indicator_code`、`area_code`（可空，全国用 `00000`）、`area_label`、`time_start`、`time_end`、`time_label`（原文，如“令和5年度”）、`granularity`（年/年度/季/月/日/时点）、`dims`（JSON：性别、年龄段等）、`unit`、`value`（DECIMAL，可空）、`note`（注记原文，如“秘匿”）、`snapshot_sha256`、`locator`、`fetched_at`。
2. `ObservationStore(dir)`：按 `source_id/table_key` 写 Parquet，DuckDB 上建视图 `observations`；重写同一张表时整体替换，不留重复行。
3. `query_readonly(sql, max_rows=1000, timeout_s=10)`：只允许单条 `SELECT`/`WITH`（用 DuckDB 的解析器或严格白名单判断），以只读方式打开；超时、超行数返回清楚的错误；结果附带所有涉及行的去重出处（要求查询里保留 `obs_id`，或提供 `with_provenance` 包装）。
4. 提供 `describe()`：列出有哪些调查、指标、地区范围、时间范围，给模型看。
5. 测试覆盖：写入、替换、只读拦截（INSERT、ATTACH、COPY、多语句、`read_csv` 等文件函数都要被拒绝）、超时、出处回溯、空值和注记保留。
