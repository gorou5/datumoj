# 目标
解析出来的 Chunk 能存进 SQLite，并用日文关键词（不分词）检索到。

# 背景
PLAN 4.2：关键词检索用 SQLite FTS5 trigram，日文不分词也能搜。

计划见 `docs/PLAN.md`，任务总表见 `docs/TASKS.md`。
- 测试全部离线：不访问网络，HTTP 一律用 `tests/fixtures/` 里的录制样本或本地假服务器。
- 依赖已锁定在 `uv.lock`，不能新增依赖，也不能改 `pyproject.toml`。确实需要新依赖时，写进 `results/IVY-009/summary.md` 并停下来问。
- `tests/fixtures/` 下已有的样本只读；需要新样本就新建文件，并在该目录的 README.md 旁另写说明文件。
- 代码注释、docstring 用中文或英文均可；标识符用英文。

# 要求
1. `ChunkStore(path)`：`upsert_document`、`upsert_chunks`（同一 `doc_key` 新快照替换旧块，保留旧快照的记录以便引用旧版本）、`get_chunk(chunk_id)`、`chunks_for(doc_key)`。
2. FTS5 表使用 `tokenize='trigram'`；索引字段为 `title_path` 拼接和 `text`；建表前检查 SQLite 版本是否支持 trigram，不支持就报错。
3. `search_fts(query, k=10, source_ids=None) -> list[Hit]`，Hit 含 `chunk_id`、`doc_key`、`locator`、`score`、`snippet`；查询先经 IVY-005 的 `normalize`。
4. 两个字以下的查询（trigram 搜不到）退回 `LIKE` 查询并在结果里标注。
5. 测试用 30 条以上人工构造的日文块，覆盖：命中、排序合理（标题命中优于正文）、按来源过滤、短查询、替换后旧块不再被搜到。

- 不建目录（数据集）索引（IVY-015）。
