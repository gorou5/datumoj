# 目标
全项目共用的数据模型和抓取记录库定下来，后续所有采集器、解析器、索引都只依赖这里的类型。

# 背景
这是接口先行的地基任务，后面 20 多个任务都按这里的字段写。见 PLAN 第 4.1 节。

计划见 `docs/PLAN.md`，任务总表见 `docs/TASKS.md`。
- 测试全部离线：不访问网络，HTTP 一律用 `tests/fixtures/` 里的录制样本或本地假服务器。
- 依赖已锁定在 `uv.lock`，不能新增依赖，也不能改 `pyproject.toml`。确实需要新依赖时，写进 `results/IVY-001/summary.md` 并停下来问。
- `tests/fixtures/` 下已有的样本只读；需要新样本就新建文件，并在该目录的 README.md 旁另写说明文件。
- 代码注释、docstring 用中文或英文均可；标识符用英文。

# 要求
1. 用 pydantic v2 定义：`Source`、`Dataset`、`Resource`、`Snapshot`、`Document`、`Chunk`、`Citation`、`FetchOutcome`（枚举：`ok`、`not_modified`、`http_error`、`network_error`、`too_large`、`blocked_by_robots`、`empty_body`、`spa_shell`）。
2. `Snapshot` 至少含：`snapshot_id`、`source_id`、`resource_url`（已去掉 API Key）、`fetched_at`（带时区）、`http_status`、`outcome`、`sha256`（失败时为空）、`size`、`content_type`、`etag`、`last_modified`、`license`、`error`。
3. `Chunk` 至少含：`chunk_id`、`doc_key`（跨次抓取稳定的文档键，如 `jp-egov-law:415AC0000000057`）、`locator`、`text`、`title_path`（如 `["個人情報の保護に関する法律","第四章","第二十七条"]`）、`snapshot_sha256`、`lang`、`published_at`/`effective_at`（可空）。
4. **locator 统一格式**：`key=value` 用 `;` 连接，key 只能取 `art`、`para`、`item`、`suppl`、`table`、`page`、`sheet`、`cell`、`row`、`entry`、`section`、`feature`。提供 `parse_locator` / `format_locator`，往返一致，非法 key 报错。
5. `Citation` = `source_id` + `resource_url` + `snapshot_sha256` + `fetched_at` + `locator`；提供 `Citation.render()` 输出一行人能读的出处。
6. `manifest.py`：SQLite 文件里有 `sources`、`resources`、`snapshots` 三张表；提供 `record_snapshot()`、`latest_snapshot(resource_url)`、`snapshots_for(source_id)`、`last_success(resource_url)`、`failure_summary(source_id)`。失败的抓取也必须写进去。
7. 写入在事务里完成；同一个 `snapshot_id` 重复写入要报错，不能静默覆盖。
8. 提供 schema 版本号表，`open_manifest(path)` 发现版本不符时报清楚的错误。
9. 测试覆盖以上每一条，包括失败记录、去 Key（URL 里的 `appId=`、`api_key=`、`key=` 参数值替换成 `REDACTED`）、locator 往返、非法 locator。
