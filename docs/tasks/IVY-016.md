# 目标
政府发布的 CSV、XLSX、ZIP 能被可靠地读成“带定位的单元格表”，编码、合并表头、注记都不出错。

# 背景
参考旧项目 `runtime/src/adapters/bodik/{text-files,excel}.ts` 的边界处理。PLAN 第 9 节踩过的坑：响应头写 UTF-8 实际是 cp932；ZIP 被误判成 XLSX；同一 ZIP 内 SJIS 和 UTF-8 成员混用。样本在 `tests/fixtures/tabular/`。

计划见 `docs/PLAN.md`，任务总表见 `docs/TASKS.md`。
- 测试全部离线：不访问网络，HTTP 一律用 `tests/fixtures/` 里的录制样本或本地假服务器。
- 依赖已锁定在 `uv.lock`，不能新增依赖，也不能改 `pyproject.toml`。确实需要新依赖时，写进 `results/IVY-016/summary.md` 并停下来问。
- `tests/fixtures/` 下已有的样本只读；需要新样本就新建文件，并在该目录的 README.md 旁另写说明文件。
- 代码注释、docstring 用中文或英文均可；标识符用英文。

# 要求
1. `sniff(bytes) -> csv|xlsx|xls|zip|unknown`：按魔数和 ZIP 中央目录判断（XLSX 是含 `[Content_Types].xml` 和 `xl/` 的 ZIP），不信扩展名和 Content-Type。
2. `read_csv(bytes)`：用 IVY-005 解码；自动判断分隔符；保留原始字符串，不自动转数字。
3. `read_xlsx(bytes)`：openpyxl 只读模式，`data_only=True` 读缓存值，**不计算公式**；记录每个单元格的 `sheet!cell` 坐标；处理合并单元格。
4. `read_zip(bytes)`：逐个成员按文件名编码（CP437 标志位 / UTF-8 标志位）正确解出文件名，再按类型递归；限制成员数量和解压总大小（防 ZIP 炸弹）。
5. 输出 `RawTable`：`cells`（行、列、原始字符串、locator）、`sheet`、`source_member`（ZIP 内路径）。
6. `detect_header(table)`：识别多行表头（统计表常见的 2–4 行表头），返回表头行范围和拼接后的列名；识别表尾的注记行（“注：”“資料：”）。
7. 测试覆盖每一条，至少包括：cp932 CSV 带 UTF-8 响应头、XLSX 合并表头、ZIP 混合编码、伪装成 XLSX 的普通 ZIP、ZIP 炸弹被拒、注记行。

# 不做
- 不做统计口径映射（各统计采集任务负责）。
- 不支持 .xls 旧格式（只识别并标记 unsupported）。
