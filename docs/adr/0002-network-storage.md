# ADR 0002：网络存储与本机数据库的边界

- 状态：已决定（2026-10-22，人定；与下方“建议”不同处以“决定”一节为准）
- 相关：DATUMOJ-TACHIBANA-103；PLAN §4.4；TACHIBANA 计划 §6.6

## 决定（2026-10-22）

- raw 照本 ADR 放 R2；**索引跟随数据一起上 R2**（chunk / 关键词索引、向量索引、观测值 Parquet 等派生数据的一致副本），本机的库和索引是可以按需从 R2 重建的工作副本。这一点取代下文“近期保留本机向量索引”的建议。
- 同步（备份）频率**按来源分别设置**：有的来源要频繁抓取，有的只需周期性，周期长短各不相同，不用全局统一的一个周期。
- 实现另排任务（不在 TACHIBANA-103 里做）；不把在线数据库文件直接放在对象存储上这一条仍然成立。

## 建议（103 提出时的原文）

本阶段将不可变 raw 接入 R2，其他库、索引、Parquet、锁和运行记录继续放在
`StorageConfig.data_dir` 的本机磁盘。下一阶段优先实现一致性备份与恢复演练，
再根据多实例访问和容灾目标决定是否迁移数据库。本 ADR 不执行迁移、备份或部署。

不把 R2 挂载目录当作 SQLite / DuckDB 的在线数据库磁盘：对象存储提供对象级操作，
不能据此假定它具备数据库要求的随机页写入、文件锁和 WAL 语义。

## SQLite：manifest、chunk、关键词、目录

| 可选做法 | 可行性与代价 | 建议 |
| --- | --- | --- |

备份应包含版本、内容校验和、完成标志、raw 前缀与快照引用、模型版本和各库的同代次清单。
先上传副本，最后发布完整代次清单；失败代次不能成为恢复入口。恢复到新目录并校验，
通过抽样出处还原后再切换。raw 的生命周期不能早于仍被 manifest / 备份引用的对象；
本阶段不自动删除对象，保留期及孤立对象清理由人另定。

## LanceDB

LanceDB / Lance 支持对象存储 URI，因而向量表放 S3 类存储具有可行性；
R2 的 endpoint、region、鉴权参数及多写入者提交机制须对锁定版本做专项验证。
不能只把当前参数改成 `s3://`：仓库的 `LanceVectorIndex` 先构造 `Path` 并创建本机目录，
模型元数据 `_meta.json`、`vectors-state.json` 也在本机。需一并处理元数据位置、
缓存、提交一致性、索引构建和失败恢复；对象请求及网络延迟会改变检索/重建成本。
建议近期保留本机向量索引，并记录模型与维度，允许从 chunk 重建。

## Parquet / DuckDB

Parquet 是适合对象存储的列式文件。DuckDB 的 httpfs 扩展可通过 S3 接口读取远端
Parquet（支持范围读取），也可将查询结果写出到对象存储；这不表示 DuckDB 的在线
`.duckdb` 文件能安全放在对象存储上。扩展安装、R2 endpoint 与凭证注入需要专门配置。

当前 `DuckDBObservationStore` 使用本机 `Path`、原子文件替换和本机 Parquet 视图；
查询还禁用了外部访问与自动扩展加载。直接换路径会破坏现有安全边界。
未来可由受信任的存储适配器加载固定对象清单，保持用户 SQL 只读且不能任意访问网络，
以不可变 Parquet 对象加版本清单发布整代数据，并另行设计压缩/合并与并发写入规则。
代价是网络延迟、小文件请求、缓存与跨文件一致性。建议先备份本机 Parquet，
再用实际查询负载验证直接读取 R2；本任务不放宽 SQL 沙箱。

### 本机体积：已证明的统计口径，真实值待填

运行 `datumoj diagnose storage --data-dir "$DATUMOJ_DATA_DIR"`，先停止所有写入者。
诊断只遍历文件大小、读取 LanceDB 表/版本元数据和行数，不构造业务存储、读向量正文、
打开 SQLite、修改元数据或创建缺失的数据目录；拒绝符号链接。异常仅报告类型，
不输出绝对路径、连接参数、模型元数据或数据内容。文件字节为逻辑长度，非磁盘分配块，
目录大小包含子目录，不能把 `directory_bytes` 各层再相加。
各顶层库/目录在 `entries`，每张表及 `chunks` / `chunks_gN` 的代次、总大小、
行数、版本数、物理数据文件数/字节数在 `vector_tables`。

同一表的版本共享不可变文件，不能把每版 `total_files_size` 相加当作历史占用。
诊断按如下方式估算“压缩（合并碎片、移除删除行）后，再清理旧版本”的空间：

- 历史或未引用数据估算 H = 物理 `data/` 字节 − 最新版本元数据 `total_files_size`。
  它包含中断写入的孤立文件，不能仅据此判断全是历史版本；有外部引用等情况导致差值异常时为 `null`。
- 已删除数据估算 D = 最新引用数据字节 × `total_deletion_file_rows` / `total_data_file_rows`。
  这是对仍占据文件空间的删除行按平均行长分摊，**不是精确可回收字节**；
  与 H 不重叠。`deletion_file_bytes` 则是实际删除位图文件大小，两者不是同一个指标。
- M = 除当前 manifest 外的版本 manifest 字节。估算可省 H + D + M，
  估算保留量 = 表总字节 − 可省量；旧格式缺字段时输出 `null`，不当成零。
- 索引文件、删除位图、事务文件和小碎片情况另列。无法无写入地测定重编码、
  小文件合并和索引重建的净变化，不把这些额外变化计入估算。
  H、M 假设旧版本已满足保留期及在途写入保护条件；实际清理可能暂不释放。
  不建议依据估算绕过保护期。保留的各代次表继续计入，不估算删表。

合成样本创建 100 行、追加 10 行、覆盖为 30 行、删除其中 10 行，另建 g1 / g2 表，
没有运行 optimize 或 cleanup。一次验收观测如下（随机事务标识/时间会使少量元数据字节变化）：

| 指标 | 合成观测（字节） |

| 最新版本引用数据；删除行 | 1,300；10 行 |
| H；D；M | 3,879；433；1,443 |

### 对象存储实验：逐项实际观察

每个实验用 `ThreadedMotoServer` 在 loopback 随机端口提供 S3 HTTP，使用独立合成 bucket、
显式测试凭证/endpoint/region 和 `allow_http`；不读取真实凭证或联系云服务。
每个连接使用独立 Lance session。生产凭证仍须仅从 `R2_ACCESS_KEY_ID`、
`R2_SECRET_ACCESS_KEY` 读入，endpoint / bucket / prefix 沿用 `StorageConfig`，
HTTPS 与日志脱敏不能照搬测试环境的 HTTP 配置。

| 操作 | 0.40.0 + moto 的断言与结果 |
| --- | --- |
| 在 `s3://` 建表 | 成功；2 行，实际产生对象，重开可读。 |
| 追加 | 成功；2→3 行；多一个数据文件，原数据文件保留。 |
| 条件删除 | 成功；删去指定 id 后剩 2 行；数据文件未改写，产生删除位图。 |
| 向量检索 | L2 top-1 为已知目标、距离 0，删除行不返回；重开连接结果一致；版本数为 3。 |
| 两个连接并发提交 | 从相同版本 1 同时追加不同 id，两次成功，重开版本 3 且三行都在；该次记录到一次 412/409 冲突响应后重试。没有证明任意混合写操作均不会冲突或丢失业务更新。 |
| 提交中断、重开 | WSGI 在数据已上传、manifest PUT 尚未发布时阻塞，杀死独立写入进程并拒绝该 PUT。重开仍是版本 1、只有原行；再追加成功，孤立数据对象仍存在。 |

没有 skip / xfail，也没有把不支持的操作包装为成功。中断实验覆盖的是**发布之前**的进程退出，
没有覆盖提交已落地但响应丢失、分片上传失败或 R2 故障；重试仍须查已提交版本，
不能据客户端异常断定“肯定未提交”。并发追加成功只证明单表提交，不是跨表事务。
`LanceVectorIndex.add` 的 delete / add 是两个独立提交，中间失败可能暂缺行；
`_meta.json`、`vectors-state.json`、SQLite 与向量表之间仍需业务代次发布。

WSGI 记录请求数、请求体字节和 GET 响应长度（不含协议头/TLS，不是计费或性能基准）。
故障门拦截的 manifest 请求没有交给 moto，不计入这些传输统计。
一次专项验收的四维、三行小样本测得：

| 单次操作 | 请求数 | 下载字节 | 上传字节 | 操作后远端对象总字节 |
| --- | ---: | ---: | ---: | ---: |
| 追加一行 | 4 | 557 | 1,384 | 3,059 |
| 按条件删除一行 | 5 | 1,680 | 1,416 | 4,475 |
| 独立 session 打开并检索 | 7 | 4,970 | 0 | 4,475 |

追加没有整份重传旧数据；删除保留原文件，存储反而增加；小表查询含元数据/列表请求，
下载量可以超过数据文件总字节 1,608。整个操作序列观测到 Range 请求，但这次独立检索
小文件均是整对象读取，不能据此声称大表查询只读少量数据。未建 ANN 索引、未测高维大表、
大对象 multipart、远端索引构建、延迟、吞吐或真实费用；moto 成功不代表真实 R2 兼容性验收。

### 三种做法的取舍与建议（待人拍板）

令 V 为需随代次保存的全向量库字节（含保留代次及必要元数据），S 为当次来源集合的
表文件字节之和，S′ 为写后来源副本大小，Δ 为新增数据/删除位图/manifest 等写入字节，
R 为元数据、检索和改写前扫描下载字节。以下为无缓存的单次运行，不含 SQLite / raw。

| 做法 | 下载 / 上传量 | 并发写入风险 | 恢复方式 | 对 `LanceVectorIndex` 的改动量 |
| --- | --- | --- | --- | --- |
| 直接读写 R2 | 普通追加约 R / Δ，小样本如上；无 ANN 的扫描、删除或索引维护可能读大量旧数据。现有 `begin_generation(copy_current=True)` 逐批读出并重写**全部当前表**，仍有约当前表大小的下载与上传，不能自动获得纯增量。 | 本地 S3 并发追加能重试，不保证任意更新/删除或跨库一致；R2 条件提交须实测。需全局租约、条件发布及明确固定表版本，清理不得破坏已发布版本。 | 重开最新已提交表只能恢复单表；业务恢复必须按最后发布清单固定各表版本和模型/状态，忽略未发布对象，校验后切换。 | 大：URI / StorageConfig 注入；两份本机 JSON 的持久化与发布；远端快照版本固定；缓存、失败重试、代次复制和生命周期设计。只换 Path 不够。 |
| 按来源分表，仅拉要写的来源 | 约 S / S′；其他来源沿用已发布对象引用。首次迁移/全量查询副本仍需全量；大来源本身仍可能很大。 | 来源表减少写入交叉，但同一来源、共享状态及全局清单仍需租约和条件发布，不能只靠 Actions concurrency。 | 停写后上传来源一致副本，最后发布同代清单；失败时忽略该轮副本，从上次有效清单恢复选中来源到新目录并校验。 | 中到大：来源→表映射；按来源 add/delete；跨来源检索 top-k 合并和过滤；逐来源候选代；状态清单记录来源对象引用。本地 Lance 读写方式可复用。 |
| 每代次整份上传 | 下载 V / 上传 V′；不做差量时每次重复传输。 | 单写本地副本容易理解；仍须防过期写入者覆盖清单，发布前检查全库一致性。 | 整代下载到新目录、校验所有副本，最后原子切换；最简单但恢复带宽/磁盘成本最高。 | 小：现有本地向量接口基本保留，增加停写快照/上传与清单发布；不应直接复制活跃库。 |

量级示例仅为预算推导：若 V = 15 GB（十进制），整代法每轮约下载 15 GB、
上传 15 GB，合计 30 GB；若来源拆分后本轮 S 仅占 10%，且 S′≈S，则为 1.5 + 1.5 = 3 GB。
10% 不是已测来源分布，实际取本机诊断与来源运行量；当前未按来源建表，不能凭表名推算 S。
直接读写的 Δ 不能按新增行数等比例外推，样本已显示小文件/提交开销及扫描下载。

**建议 103 近期优先按来源分表并保留本地读写工作副本**：满足“每轮不全库传输”，
复用现有本地恢复机制，同时把真实 R2 的 Lance 提交兼容性从首轮发布路径中移开。
整代法保留作首次导入、恢复演练与低频兜底，不作为常规定时路径。
直接读写在锁定版本上已证明基本可行，应作为后续优化候选；如果真实体积集中在单一来源，
或 S 仍超过 runner 磁盘/时限，再优先推进真实 R2 验证与“固定 Lance 版本替代整表候选复制”的设计。
源内再拆分或改代次机制均是后续任务，不在本任务实现。
人需确认来源粒度、实际体积分布、版本保留期、恢复时间目标和 103 最终路线。

SQLite 约 1.8G 的背景值同样未经本任务测量。**近期不建议仅因这个数值就按来源拆库**：
manifest、chunks、FTS 的全局身份、水位、跨来源查询及发布事务会增加迁移复杂度，
拆库本身也不会压缩正文/历史行。先保留本机 SQLite 的一致备份，按文件/校验和复用
未变副本；发生变化的库仍需传整份一致副本，不能称其为增量页同步。
若每轮确实重传 1.8 GB，下载+上传约 3.6 GB（预算假设），应单独测运行时间/变化量再决定拆分。
不能复制活跃主库而遗漏 WAL；本诊断的文件大小清单不是一致备份。

## 补充（MAPLE-115，2026-10-25）
