# ADR 0005：状态代次、条件发布与写入租约

- 状态：**提议，待人审定**
- 日期：2026-10-23
- 契约任务：DATUMOJ-MAPLE-001
- 相关：[ADR 0002](0002-network-storage.md)、[ADR 0004](0004-evidence-identity.md)

## 决定与边界

R2 保存完整、可恢复的状态代次，本机是可重建的工作副本。每次来源运行完成后，
发布一个包含已发布状态的一致代次。来源 `sources/*.yaml` 的 `schedule` 就是
Actions 抓取频率；本版本不增加独立的状态上传频率字段，也不使用全局统一周期。
失败运行不能把 staged / failed 产物变成已发布、可查询的 current。

本 ADR 只定义模型和原子操作契约，不实现 S3、推送、拉取、租约管理或工作流。
向量存法由 101 验证决定；这里记录覆盖范围，不要求 LanceDB 目录、归档或远程表中的任何一种。

## 对象布局与清单

所有键都相对于配置的存储前缀，不包含 endpoint、bucket 或本机路径。

| 相对键 | 内容与用途 |
| --- | --- |
| `copies/sha256/<64 位小写 SHA256>` | 不可变的 SQLite 块或整文件副本，按实际上传字节寻址；同内容可跨库、跨代复用。 |
| `generations/<n>.json` | `StateGeneration` JSON，n 从 1 开始，清单不可变。 |
| `current.json` | 仅含 `{"generation": n}` 的当前有效代次指针，使用条件操作更新。 |
| `write-lease.json` | `WriteLease` JSON，整个状态命名空间共用一个写入租约。 |
| `raw/…` | 不可变 raw 对象；具体快照到 raw 的映射保留在 manifest 中，清单的 raw_prefix 指向它。 |

`raw_prefix` 是命名空间内的相对前缀，可以配置为其他相对前缀；不是 URL。
不得自动删除仍被任一保留代次引用的副本、raw 或向量对象。本版本不实现垃圾回收。

`StoreCopy` 只有 `name`（逻辑名）、`key`、`sha256`、`size_bytes`、`format`。
清单至少有一个副本，逻辑名不能重复。逻辑名用于恢复映射，不是任意本机写入路径；
恢复实现必须校验相对键和允许的逻辑名，拒绝绝对路径、路径穿越及未知格式，
先下载到临时目录并校验字节数和 SHA256，再交给对应库打开。

完整状态必须列出实际启用的 manifest、chunks、catalog、changes、
observations 库及其 Parquet 文件，以及恢复所需的 runs、control、vectors-state 元数据。
关键词索引不进入新代次，由恢复出的当前已发布 chunks 重建（见下节）；
推送前仍检查本地关键词索引不含未发布块。
多个文件分别给出稳定且唯一的逻辑名，例如 `parquet/<相对文件名>`。
不能漏掉库所引用的文件；不启用的组件无需虚构空文件。raw 不重复打包，locks 和 logs
不作为恢复状态。向量能保留的对象由 101 的存储方案确定；不保留时必须能由 chunks
及模型元数据重建，恢复后重新核对实际覆盖，不能仅凭覆盖计数声称索引可用。

`StateGeneration` 的字段为：

| 字段 | 约束与含义 |
| --- | --- |
| `generation` / `previous_generation` | 正整数；第一代的 previous 为 null，其余必须是 n−1。 |
| `created_at` | 同一状态副本制作完成后的带时区时间，不是数据发布时间。 |
| `writer` | `{kind: actions \| local, run_id}`，记录这份状态的生成者。 |
| `stores` | `list[StoreCopy]`，包含恢复该代状态必需的全部副本。 |
| `raw_prefix` | 快照所依赖的 raw 命名空间；恢复时还须验证被引用的 raw 存在且哈希正确。 |
| `vector_coverage` | null 或 `{model, version, dim, embedded_chunks, pending_chunks}`；dim ≥1，计数 ≥0。 |
| `last_successful_runs` | `{source_id: {run_id, finished_at}}`；完成时间带时区且不晚于 created_at；无成功运行的来源不填。 |

上述整数拒绝布尔值、字符串和小数。模型拒绝未声明字段。
SHA256 保证副本完整性，不替代 snapshot_id、资源身份或数据日期；出处仍按 ADR 0004
从副本中的快照与 raw 还原。没有数据日期仍是 `no_data_date`，不得用代次时间填补。
单个 JSON 的结构校验不能证明对象已上传或各库一致，这些必须由发布/恢复实现检查。
JSON Schema 由模型导出；跨字段的代次连续性、逻辑名唯一性及时间顺序由模型校验器检查。

## 一致副本

持有云端租约并不自动冻结本地数据库。制作副本时必须阻止所有本地写入者推进状态，
等待本地发布点完成，固定同一已发布状态边界，再依次制作所有库和附属文件的副本。
也可使用经验证能保留同一边界的快照机制；不能各库各取一个不同的最新时刻。

SQLite 必须用 **backup API**，不能直接复制正在写入的主文件或漏掉 WAL。
DuckDB、Parquet、向量文件及其元数据也必须在同一冻结边界下用各自支持的一致导出方式
制作。完成副本后才恢复本地写入；上传使用这些固定副本，不重新读取变化中的在线文件。
清单中的成功运行信息和向量覆盖必须来自同一边界。未发布产物不得进入恢复后的
current / 可查询集合，也不能因存在于某个文件中就被提升为已发布。

### SQLite 分块与关键词重建（MAPLE-112）

新推送将 manifest、chunks、catalog、changes 等 SQLite 一致副本按 **256 KiB
（262,144 字节）** 固定切块，是 4096 字节页的 64 倍；最后一块可短于此大小。
每块用自己的 SHA256 存为 `copies/sha256/<sha>`，使用一次副本命名空间 list
判断已有对象，仅上传缺失内容。小文件（runs、control 等）、Parquet、DuckDB
以及 Lance 不可变数据文件仍按整文件寻址，不改变向量的存法。

直接复用 `StoreCopy`，无需修改模型：

| 逻辑名 | format | 校验与恢复语义 |
| --- | --- | --- |
| `<库名>.blocks/0`、`<库名>.blocks/1`、… | `sqlite-block-v1` | 从 0 连续编号，清单中按数字递增排列；每条记录对应一个实际块对象及其字节数、SHA256。 |
| `<库名>`（如 `chunks.sqlite`） | `sqlite-blocks-v1` | 整文件的字节数和 SHA256；key 保持 `copies/sha256/<整文件 SHA256>`，仅作校验记录，不上传或下载整库对象。 |

恢复先拒绝缺块、乱序、大小不符、无整库校验记录或混用新旧格式的布局，
再流式读取各块，逐块校验并按数字顺序拼接，同时计算整文件 SHA256 和字节数。
所有库校验成功后才打开数据库；校验记录不计作额外的存储字节。
旧 102 / 103 代次的 `format=sqlite` 整文件副本（包括 keyword.sqlite）仍可恢复；
旧代次若有关键词库就保留它，没有则从 chunks 重建。新代次一律省略 keyword.sqlite。

2026-10-23 的本机副本实测使用真实 `SqliteChunkStore` / `SqliteKeywordIndex`
写入路径，模拟 24 小时、每小时 67 份文档，半数为已有文档的新版本；
每小时通过 backup API 制作一致副本。整文件累计 **47.6 GB**，256 KiB 分块后
chunks.sqlite 只新增 **0.29 GB**（每小时中位数 **9 MB**），同期实际数据增长
**233 MB**。keyword.sqlite 因 FTS5 段合并仍新增 **2.75 GB**，峰值一小时
**513 MB**，因此不将其作为代次副本。

恢复复用 `SqliteChunkStore.iter_chunks()` 对 current_versions 的选择和
`SqliteKeywordIndex` 批量写入实现，只索引当前已发布块，历史与暂存版本不提升为
可检索状态。重建后的 schema、索引发布边界及原有出处抽样校验全部通过后，
才将临时目录交给调用方；失败不交出目录。`raw=remote` 只核对 raw 键库存，
重建只读已恢复的 chunks，不下载原始正文。

代价是每次无关键词库的恢复都要重建索引。上述本机全量 **27,880 块用时 65 秒**，
恢复耗时因此增加下载、拼接、校验之外的一次索引重建；这不是其他机器的性能保证。
分块能减少新增存储和上传量，恢复仍须读取全部被引用块。本版本不删除任何旧对象。

## 有效代次与发布顺序

**有效代次**必须满足：全部引用副本已上传并通过大小/哈希检查，依赖 raw 可用，
一致清单已写入，且 `current.json` 已通过条件写入切到它。只完成上传或只有清单的
中途失败代次不是有效代次；禁止列举 generations 后选最大编号作为恢复入口。
历史有效代次可由当前清单的 previous 链回溯；指针推进不删除历史。

1. 先取得有效写入租约，再读取 current 的字节和同一版本的 ETag。空命名空间以 n=1
   开始；否则只准备当前有效代次 n 的下一代 n+1，previous 必须是 n。
2. 从该代状态制作一致副本、计算 SHA256 并上传。内容寻址副本用 `put_if_absent`，
   已存在时须核对已有字节的哈希/大小；不覆盖不匹配对象。
3. 用 `put_if_absent("generations/<n+1>.json", bytes)` 写清单。冲突时不得覆盖、
   不得给相同编号换一份内容，也不得把编号跳到 n+2 继续本轮。
4. 发布前确认租约仍属于自己、尚未过期，候选清单仍是自己的完整候选，
   再用原 current ETag 执行 `put_if_match("current.json", next, etag)`。
   首代没有 current，使用 `put_if_absent("current.json", first)` 初始化，
   不能用无条件 put，也不建立指向虚构第 0 代的占位指针。
5. CAS 成功是发布点。只有紧接当前有效代次且赢得 CAS 的候选成功；
   清单创建或指针更新被抢先时，本轮作废，停止发布。不得带着旧候选重读 ETag 后强写。

两个写入者读到同一指针时，只能有一个创建下一代清单，也只能有一个用旧指针 ETag
更新指针。ETag 是不透明比较令牌，必须原样传回，不作内容哈希使用。current 单调递增，
不回写旧编号；回滚业务内容也要制作新的下一代。读取不存在返回 None；条件创建已存在、
条件更新/删除对象不存在或 ETag 不符都抛 `PreconditionFailed`，失败不修改对象。
网络错误不能伪装成条件失败。请求结果不明时需读回对象核实，不能仅因超时就声称未发布。

清单写入后指针失败可能留下占住下一编号的孤立清单。它不会自动生效，也不能被新内容
覆盖。后续持租约的恢复操作可重新验证该清单全部副本、一致性和 previous，确认 current
仍是其上一代后，显式续完**同一份清单**的条件发布；writer 保留原生成者。
这不是竞争失败的原轮继续重试。无法证明完整或发现损坏时停止并报告，需要人审定修复，
不能跳号、无条件覆盖或自动删除。恢复实施及证据由后续任务提供。

## 写入租约

`WriteLease` 只有 `holder`、`token`、`acquired_at`、`expires_at`。holder 为
`actions/<run_id>` 或 `local/<run_id>`；每次重新取得租约生成不可复用的随机 token，
续期保留 holder、token 和 acquired_at。时间必须带时区，expires_at 严格晚于 acquired_at。

- 取得：对象不存在时 `put_if_absent`；两个取得者只能有一个成功。有效租约存在则拒绝，
  本地与 Actions 遵守同样的规则。
- 续期：读取当前对象与 ETag，核对 holder/token 且尚未到期，用 `put_if_match` 延长
  expires_at；新到期时间须晚于旧到期时间。条件失败或已到期立即停止写入，不能复活旧租约。
- 释放：核对 holder/token，以当前 ETag 执行 `delete_if_match`；旧持有者不能删除他人新租约。
- 接管：`--force` **只能接管已经过期的租约**（now ≥ expires_at）。读回、校验过期后，
  用旧 ETag `put_if_match` 换成新 holder、新 token 和新时间。期间若被续期或抢先接管，
  CAS 失败，本轮作废；不能先删再建。未过期的租约、格式损坏或不能可信判断时间时，
  `--force` 也不能绕过检查。

持有者失去租约或到期后必须停止所有后续状态写入，尤其不能发布 current。所有写入者
必须配合协议并使用可信时钟，保留足够的续期和发布余量。租约对象和指针是两个键，
对象存储没有跨键事务：一次租约检查不是服务端 fencing 保证，不能阻止任意停顿后
违规继续写的进程。不可变清单、单调编号及指针 CAS 保证同一上一代只有一个发布结果；
不宣称该基础接口能提供跨对象事务或对不守约客户端的强制隔离。

## 验证与后续工作

`StateObjectStoreSuite` 可由真实适配器继承，覆盖二进制/空对象、列表、条件失败不修改、
过期 ETag 的更新/删除拒绝及双线程条件创建/更新竞争。内存假实现使用锁保证原子性，
其递增 ETag 不代表真实 S3 ETag 算法。模型测试覆盖 JSON 往返、Schema 和校验边界。

本任务没有访问真实 R2、迁移数据或运行任何租约/发布流程。102、104、106 等后续任务
负责 S3 条件操作兼容、推送/拉取、崩溃恢复、租约时钟和失租演练；S3 测试必须离线使用
moto 或本地假服务。凭据仅按项目环境变量读取，日志不得暴露凭据、endpoint、bucket、
租约 token 或原始数据；只记录计数、来源 ID、代次号与相对对象键。
人类需审定本 ADR 的清单边界、孤立清单恢复及租约规则；不能把契约测试通过当成云端发布已验证。
