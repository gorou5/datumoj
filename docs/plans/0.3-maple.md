## 1. 一句话

先把**证据的身份和版本**做对（同样的字节、同样的编号不再串到别的资源或别的表），再让资料库**在自己的 NAS 上按来源定时自己更新**，原始文件和索引都放在 NAS 上的 S3 兼容存储里，本机随时可以拉下来用；同时把来源扩到**欧美**和几类日本统计数据。

## 2. 为什么做这些

- **证据正确性有缺口**（2026-10-23 Codex 审核，10 个合成复现在当前 `main` 上全部复现）：解析缓存只按内容哈希判断，同样字节的另一个资源会被跳过；旧失败重试会把当前版本倒退；同 SHA 的引用会指到最新的另一个 URL；`obs_id` 跨表重名时附上另一张表的出处。这些会给出“看起来带证据、实际关联错误”的结果，扩大来源和上云之前必须先修。
- **持续更新离不开常开的运行环境**：0.2 的抓取都在本机跑，机器休眠或关机就中断；气象厅的 feed 只保留约 7 天，断几天就永久缺数据。运行环境原定 GitHub Actions + R2（2026-10-22），**2026-10-25 改为自有 NAS**：NAS 常开、从日本的家用网络访问政府站点（不再有海外 IP 被拒的风险），数据不出自己的设备。设备晚几天到货，到货前本机的定时抓取不停。
- **ADR 0002 已定但没实现**：索引跟随数据放到网络存储，本机的库和索引是可以按需从网络存储重建的工作副本；同步频率按来源分别设置。网络存储从 R2 改为 NAS 上的 S3 兼容服务，代码按 S3 接口写，只换 endpoint（ADR 0002 补充，任务 115）。
- **0.2 留下的观察**：新来源的一周试运行（原 0.2 H3）要在常开的运行环境上做才有意义，移到本版本（2026-10-22），在 NAS 上做。
- **覆盖面**：总计划里欧美来源排在这一阶段（`docs/PLAN.md` 第 5 节）；日本的 e-Stat API 和几类命名文件（0.2 计划第 4 节写“放到 0.3 或之后”）一并做。

## 3. 目标（MAPLE 完成的标准）

0. **证据正确性**（检查点 m0，先于其他检查点）：第 6.0 节的问题全部有回归测试并修复；同字节多资源、A→B→A、旧失败后新成功、同 `obs_id` 多表、聚合、日期筛选、raw 损坏、运行中断都有明确且正确的行为；本机现有数据在副本上完成只读诊断和迁移演练。
1. **NAS 定时运行**：NAS 按来源各自的频率定时抓取、解析、建索引（含向量），结果写进 NAS 上的状态存储；同一时间只有一个写入者；一次运行失败不会留下半截状态。
2. **状态在 NAS 上，可重建**：raw、各库（manifest、chunk、关键词、目录、变化）、观测值、向量在 NAS 的状态存储上有一致的代次；下一次运行和本机都能从它恢复，恢复后能还原任意一条出处。
3. **本机拉取**：`datumoj pull` 把 NAS 上最新的完整代次拉到本机，MCP 照常在本机回答；本机的定时抓取和 NAS 不能同时写。
4. **一周试运行**：所有来源在 NAS 上连续跑一周，提醒和每周变化报告合理，短保留来源（JMA）没有时间缺口（原 0.2 H3）。
5. **欧美来源入库**：data.europa.eu、Eurostat、英德法荷四个开放数据门户、Federal Register、世界银行 WDI。
6. **日本来源入库**：e-Stat API（精选表）、国土数值信息、2024 经济普查、医疗开放数据、ABR 地址（各自的范围在 H2 定稿）。
7. **多语言检索**：英语和欧洲语言的问题也能检索到对应资料；关键词相关性门槛在这些语言上同样有效。
8. **评测**：新增欧美、日本新来源、多语言、跨国比较几类题，共 30 题以上；和 IVY、TACHIBANA 的题一起全部达标。
9. **真实问答验收**：在 Claude Code 里注册 MCP（本机拉取的数据），用日、中、英三种语言提问，回答带出处和断言级别。

## 4. 不做

- **部署到 Cloudflare Workers / Cron Triggers、D1**：不做；数据库不迁到 D1（ADR 0002：不把在线数据库文件放在对象存储上，在运行机上运行，代次备份到网络存储）。
- **GitHub Actions 定时运行和 R2**（2026-10-25）：已做完的工作流（105）和 S3 写法保留，但不部署、不建 bucket；以后要上云时再启用。**不用自托管 runner**：公开仓库的自托管 runner 会被外部 PR 利用。
- **对外公开的查询服务**：NAS 上的数据只给本项目的运行和本机拉取用，不开放公共访问；NAS 不向公网开放端口，本机在局域网或私有 VPN 里访问。
- **需要 Key 的美国来源**：GovInfo、Data.gov（api.data.gov Key）等 Key 到位以后再排。
- **KKJ 采购公告**：仍不在本版本。
- **数据清理**：仍由另外的 batch 机制处理；网络存储上的旧代次保留期由人另定，本版本不自动删除。
- **主动推送**（邮件、聊天通知）：提醒和报告仍只在命令行、管理页面和状态存储里的报告文件里。
- **中、俄、土、印等其他国家**：仍不做。
- **气象厅平年值、国土地理院标高**：不在本版本。

### 6.1 契约修订（先做，由人审查）
- **状态代次清单**（`StateGeneration`）：代次号、生成时间、写入者（Actions 运行号或本机）、各库副本的对象键和 SHA256、raw 前缀、向量模型和版本、向量覆盖（已建向量的块数和待建块数）、包含的来源及各自的最后成功运行。只有清单最后发布、全部副本都已上传的代次才是有效代次（ADR 0002）。
- **写入租约**：状态存储上一个租约对象（持有者、取得时间、到期时间），用对象存储的条件写入（`If-None-Match` / `If-Match`）原子地取得、续期和释放；发布新代次时也用条件写入，只有代次号紧接着当前有效代次时才成功。
- **来源的同步频率**：`sources/*.yaml` 已有 `schedule`（如 `hourly`、`daily`），本版本明确它就是运行机（NAS）上的抓取频率；需要时加上“状态上传频率”，不加就与抓取频率相同。
- 修订会影响已有代码，契约任务的 `unprotect` 要明确列出允许改的已有测试。

### 6.2 状态存储（ADR 0002 的实现；2026-10-25 起放在 NAS）
- **存储**：NAS 上跑一个 S3 兼容服务（如 MinIO），建专用 bucket 和只给本项目用的访问密钥。代码按 S3 接口访问，只换 endpoint；R2 的写法保留（任务 115 把配置名改成通用的 S3 写法，旧名兼容）。
- **条件写入是前提**：租约和代次发布依赖条件写入（PUT 的 `If-None-Match` / `If-Match`，DELETE 的 `If-Match`）。运行前探测存储是否支持，不支持就拒绝运行，不退回无保护的写法（任务 116）；到货后先实测（H0）。
- **一致的副本**：SQLite 用 backup API、DuckDB 用导出或停写后复制，不直接复制正在写的文件；同一代次里各库是同一时刻的状态。
- **上传和发布**：先上传副本，最后写代次清单；中途失败的代次不会成为恢复入口。
- **恢复**：恢复到新目录，校验 SHA256，抽样还原出处后再切换。
- **体积**：本机向量库现有 15G，先查是否是没压缩的历史版本；每次运行不应整份下载和上传。NAS 在局域网里，带宽和费用不再是主要约束，但仍只传增量。

### 6.3 NAS 运行
- **形态**：NAS 上用容器（Docker / compose）跑 DATUMOJ，NAS 自带的计划任务（或容器内的定时器）每小时调用一次已有的 `datumoj cloud run`：取租约 → 从状态存储恢复最新代次 → 抓取到期来源 → 解析和建索引（增量）→ 发布新代次。仓库提供镜像定义、compose 示例和部署说明（任务 116），不含任何凭证。
- **向量**：NAS 上能跑 Ollama 和 bge-m3 就在 NAS 上只给新增块建向量；硬件不够时由本机建向量再发布，代次清单照常记录向量覆盖。到货后按实际硬件定（H0）。第一次全量在本机建好，作为第一个代次（H3）。
- **凭证**：状态存储的访问密钥、e-Stat appId 只放 NAS 上的运行环境变量文件和本机的 `.env`，不进仓库、不进镜像。
- **单写入者**：NAS 和本机写入前都要先取得状态存储上的写入租约（6.1），拿不到就不写；发布代次用条件写入，检查和发布之间被别人抢先时发布失败、这一轮作废。租约到期前持有者要续期；`--force` 只接管已过期的租约。NAS 接手某个来源后，本机对这个来源的定时抓取要停掉。
- **网络**：NAS 不向公网开放端口；本机拉取在局域网或私有 VPN 里进行。
- **GitHub Actions**：`cloud-run.yml` 保留但去掉定时触发，只留手动触发（定时只在默认分支生效，MAPLE 合进 `main` 后会每小时跑一次并因缺凭证失败）；文档写明当前运行环境是 NAS。

### 6.4 本机拉取
- `datumoj pull`：从 NAS 的状态存储下载最新的有效代次到本机（只下载有变化的部分），校验后切换；MCP 和 `datumoj search` 读本机副本。
- 拉取后本机的库是只读工作副本，回答里的数据截止时间写代次的生成时间。

### 6.5 监控和报告
- 运行记录、提醒和每周变化报告随代次进状态存储；`datumoj schedule status` 和管理页面读本机拉下来的副本。
- NAS 上的运行本身失败（容器起不来、超时、NAS 断电）也要能发现：监控按“预期频率内没有成功运行”提醒，本机拉取时显示最后一次成功运行的时间。

### 6.6 欧美来源
- **目录门户**：CKAN 系（英、德、荷）复用 IVY 的 CKAN 采集器，只加配置和必要的差异处理；data.gouv.fr（udata）和 data.europa.eu 各写一个适配器，产出同样的 `Dataset`。
- **统计**：Eurostat（SDMX）和 WDI 产出观测值，进 `query_sql`；查询结果必须保留 `obs_id`，才能生成逐行出处；单位、年份、地区编码原样记录，跨国比较时不自行换算货币。
- **Federal Register**：按文件（document number）抓全文，按节切块，locator 写节标题路径；按发布日期增量。

### 6.7 多语言检索
- 关键词索引现在用 FTS5 的 trigram 分词，对英语和欧洲语言也能工作，但相关性门槛（TACHIBANA-501）是在日语、中文问题上校准的，要在英语等语言上重新校准。
- 向量一侧 bge-m3 本身是多语言的，跨语言检索（用中文问欧盟数据）作为评测题覆盖。

## 9. 风险

| 风险 | 应对 |
|---|---|
| NAS 晚几天到货，期间 JMA 断档 | 到货、真实运行通过之前本机定时抓取不停；JMA feed 保留约 7 天，接手当天核对无缺口 |
| NAS 上的 S3 兼容服务不支持条件写入 | 116 运行前探测，不支持就拒绝运行；H0 实测，换支持的服务或版本 |
| NAS 断电、宕机或容器停掉 | 监控按“预期频率内没有成功运行”提醒（117）；JMA 的缺口单独提醒；按需加 UPS |
| NAS 磁盘不够、单次运行太久 | 每次只跑到期来源；向量增量；库按来源拆分（101 的结论）；首次全量在本机做 |
| NAS 上 CPU 建向量太慢 | 只给新块建向量；单次运行设上限，没建完的下次继续，不阻塞发布；代次清单记录向量覆盖，还没建向量的块照常能被关键词检索找到，`search_docs` 和 `datumoj pull` 在覆盖不全时注明“向量覆盖 x / y” |
| 两个写入者（NAS 与本机）同时写，状态互相覆盖 | 状态存储上的写入租约 + 条件发布；代次清单记录写入者 |
| 中途失败留下半截代次 | 先传副本、最后发布清单；恢复只认已发布的代次 |
| NAS 暴露到公网，或凭证进了仓库和镜像 | 不开放公网端口，局域网或私有 VPN 访问；凭证只放 NAS 的环境变量文件和本机 `.env`；日志只写计数和来源 ID；CI 的密钥扫描覆盖 |
| NAS 存储增长 | 只存增量；不自动删除但记录体积；每周报告附上存储用量 |
| 欧美门户接口各不相同 | CKAN 系复用；非 CKAN 的各写适配器，产出同一个 `Dataset` |
| 跨国比较口径不一致，模型自行换算 | 回答规则禁止自行换算货币和口径；数值只从 `query_sql` 取 |
| 修复身份和发布时直接全量重解析，把旧版本倒退放大 | 先契约和失败用例（002），再迁移设计；真实数据只在副本上演练，比对通过才切换 |
| 身份字段加多了，契约膨胀 | 只加恢复和引用确实需要的字段，不做通用元数据平台（002 人审） |
| 重做的任务丢失前几轮已确认的要求 | 审查确认的要求写进任务文件的固定条目 |

## 10. 和 TACHIBANA 的关系

- TACHIBANA（0.2）的开发已完成（PR #15），H4 真实问答验收待做；MAPLE 在其合并后的 `main` 上开发。IVY 和 TACHIBANA 的评测题和门槛继续作为回归基线。

## 11. 以后的方向（不在本版本，2026-10-22 记录）

- **单源失真验证**（https://plan.datumoj.com/verify/ ，30 例）和**多源融合分析**（https://plan.datumoj.com/cases/ ，100 例）是之后的方向：同一指标用 3 个以上独立来源交叉核对（例如官方 GDP 对夜光、贸易镜像、超额死亡），或把多个来源叠加回答一个问题。需要的来源以国际组织为主（IMF、OECD、世界银行、联合国各机构、WHO、BIS、ILO、UN COMTRADE、Copernicus 等），以及各国统计局。
- 本版本的 Eurostat、WDI 和跨国比较的回答规则（702）是这个方向的第一步：数值只从 `query_sql` 取、口径和单位原样记录、不自行换算，这些规则以后做融合和核对时同样适用。
- **法国政府开放数据（Hugging Face `AgentPublic/open_government`）**：https://huggingface.co/datasets/AgentPublic/open_government ，Parquet，约 2,400 万行，法语、英语等 20 多种语言的政府和监管文本（例如 AMF 的公告和招股书），数据集标注 Apache-2.0。**只记录，不抓取**；以后处理时再核对各子集原始来源的许可。补充说明见 https://plan.datumoj.com/hf-gov/ （Hugging Face 上 389 个 government 数据集的全量调查）：它约 380B tokens、16 个集合，是 LLM 训练语料，没有结构化字段和逐条出处，与 DATUMOJ 的“注册层 + 逐条证据链”不是一类东西。
- **DATUMOJ 自己发布数据集**（同一调查的建议）：把注册层（官方资源的机构、URL、许可、核查时间）和带逐条出处的垂直登记库发成数据集；许可和出处先行。HF 上日本政府数据目前为零。
