## 0. 流程（本版本起）

1. **计划 PR**：只含计划文件，由团队审核。v0.2 已随 PR #3 合并，本次修订另提计划 PR。
2. **任务 PR**：计划合并后拆成任务文件（`docs/tasks/DATUMOJ-TACHIBANA-*.md`），单独提 PR；合并后才同步给调度器开工。
3. **版本分支**：开工时从最新的 `main` 建 `feature/0.2`，主仓库目录切到这个分支（调度器把任务合并进当前分支）。TACHIBANA 的代码、测试、配置都在这个分支上开发和推送，不直接提交或推送 `main`；版本开发完、验收通过后，从 `feature/0.2` 向 `main` 提 PR。
4. **发布**：PR 合并后在 `main` 上打 tag（`v0.2.0-tachibana`，检查点为 `-m<N>`）。
5. **提交规则**：代码、文档、配置分开提交；不属于同一批次的改动不混在一起；计划文件只出现在计划和任务的 PR 里。
6. **团队规范**：协作、安全、描述和证据标准按 `AGENTS.md`、`CONTRIBUTING.md`、`SECURITY.md`、`docs/interoperability.md`；与本计划冲突的地方按 `docs/PLAN.md` 第 1.1 节的取舍。
7. **里程碑记录**：上面每个节点（计划、任务 PR、开工、各检查点、发布）完成时更新 `plan/milestones.json`，单独提 PR 进 `main`；对应 PR 合并才算完成（`docs/PLAN.md` 第 8.1 节）。

## 1. 一句话

把资料库从“能查法令、目录、统计、气象”扩到**政策网页和 PDF**，补上 IVY 留下的检索缺口，让人**每周知道资料库里变了什么**，并为以后落到网络存储做好存储适配层。

## 2. 为什么做这些

IVY 完成后，链路已经打通，抓取也能按开关定时运行（IVY-107、610），但还有几类缺口：

- **覆盖面不够**：“大阪市の AI スタートアップ支援策”这类问题答不出，因为缺省厅和自治体的政策网页。IVY 验收（H6 第 7 题）时，检索只命中了含“大阪”字样的无关旧法令。
- **检索质量的已知缺口**（IVY 验收记录第 4 节）：
  - 关键词检索没有相关性门槛：问资料库里没有的东西时，常见词也会命中无关内容，缺口状态却判为 ok。
  - e-Stat 统计表只能用 SQL 查到，`search_docs` 和 `search_catalog` 都找不到。
  - 目录检索的结果还原不到它来自哪一次快照。
- **缺少运营视角**：抓取失败只在运行记录里，没有提醒；资料多了以后，人需要知道“这周变了什么”。
- **运行环境要换**：运行时以后要落到网络存储（Cloudflare R2 等），现在各处直接读本机的 `data/` 目录，换不过去。
- **团队规范**：团队的描述标准要求模块和数据源有机器可读的描述（`schemas/registry/`），现在只有采集器自用的 `sources/*.yaml`。

## 3. 目标（TACHIBANA 完成的标准）

1. **政策网页入库**：种子清单内的省厅和自治体页面，以及页面链接的 PDF 都能抓到并按节、按页切块，能引用到节和页码；SPA 外壳和空页面会被识别出来，不会当作成功。
2. **BODIK 入库**：复用 CKAN 采集器，再加上 DataStore 数据读取。
3. **抓取监控**：基于 IVY-107 的运行记录，连续失败、解析失败率突然升高、超过预期频率没有成功抓取时，`datumoj schedule status` 和管理页面（`datumoj admin`）给出提醒；失败按“来源不可用 / 频率受限 / 认证失败 / 数据格式变化”分类。
4. **每周变化报告**：每周在 `data/reports/` 生成一份 Markdown，按来源列出新增、修改、删除和失败，每条都带出处。
5. **IVY 遗留的检索缺口补上**：
   - 关键词检索有相关性门槛，资料库里没有的问题判为 `zero_hits`；
   - e-Stat 统计表作为数据集进入目录检索；
   - 目录检索的结果能还原到快照。
6. **存储适配层**：数据位置只由一处配置决定；`RawStore` 有 S3 兼容（R2）实现，并通过与本机实现相同的契约测试；SQLite 类的库怎么上网络存储有 ADR。
7. **注册层描述导出**：`datumoj registry export` 从 `sources/*.yaml` 生成 `catalog/*.json`，通过 `tests/validate_schemas.py`；不知道的字段填 `unknown`。
8. **评测**：新增政策网页、变化、注入三类题，以及覆盖第 5 条的题，共 25 题以上；和 IVY 的 60 题一起全部达标。
9. **真实问答验收**：在 Claude Code 里注册 MCP，亲手回答第 2 节的政策问题，回答带出处和断言级别，不判断补助是否适用。

## 4. 不做

- **KKJ 采购公告**：2026-10-22 讨论后移出本版本，以后再定。v0.2 草案里为它准备的 `Redaction` 契约、`search_notices` 工具和采购问答规则一并移出。
- **部署到 Cloudflare**：本版本只做存储适配层和 R2 实现，真正部署（Workers、Cron Triggers、生产 R2 桶）等账号、凭证和部署流程定下来以后另排。
- **在 GitHub Actions 上运行、索引上 R2**（2026-10-22 决定移到 0.3）：R2 凭证只放在 GitHub Actions 的 secrets 里，抓取要在 Actions 上跑；这需要 raw 和索引都上 R2、本机或下一次运行能从 R2 重建（ADR 0002 的实现）、按来源设同步频率。本版本的真实抓取在本机进行，raw 用本机存储。
- **数据清理**：保留和清理由另外的 batch 机制处理，DATUMOJ 不做（`docs/PLAN.md` 第 13 节第 12 条）。
- **强制填写来源说明**：保存目的、保留期限等说明字段不作硬性要求。
- **OCR**：扫描件 PDF 只标记 `needs_ocr` 并统计数量，不识别。
- **登录后才能看的页面**、表单提交、需要执行 JavaScript 才能看到正文的页面（只识别为 SPA 外壳）。
- **全站爬取**：政策网页只抓种子清单和限定深度内的链接。
- **补助是否适用**等个案判断。
- **主动推送**（邮件、聊天通知）：变化报告只写到本地文件，提醒只在命令行和管理页面里显示。
- **定时与开关**：IVY-107、610 已完成，本版本不再重做。
- e-Stat API、国土数值信息、经济普查 2024、医疗开放数据、ABR 地址、气象厅平年值、国土地理院标高：放到 0.3 或之后。
- 欧美来源：0.3 以后。

## 6. 设计上的新增内容

### 6.1 契约修订（先做，由人审查）
- **`ChangeEvent`**：来源、doc_key、类型（新增 / 修改 / 删除 / 抓取失败 / 解析失败）、新旧快照的 sha256、发现时间、摘要。要能引用到快照。
- **`Document.kind`**：`law`、`html_page`、`pdf`、`dataset`、`bulletin`，检索时可以按类型过滤。
- **快照之间的父子关系**：网页 → 附件 PDF，回答时可以说明“这份 PDF 是从哪个页面链接过来的”。
- **`Dataset` 记录来源快照**（IVY-603 提出的缺口）：加上 `snapshot_sha256` 和 `locator`，目录检索结果能用 `cite` 还原。
- **抓取失败的分类**：运行记录和 manifest 里的失败带上类型（`source_unavailable`、`rate_limited`、`auth_failed`、`format_changed`、其他）和能否重试（团队规范 `docs/data-sources.md` §4）。
- 修订会影响 IVY 已有的代码，所以契约修订任务的 `unprotect` 要明确列出哪些已有测试允许改（调度器 A-004 规则）。

### 6.2 PDF 与 HTML
- **PDF**：用 pypdfium2 抽文本、pdfplumber 抽表格（表格可选）；每页一个 Chunk，locator 写成 `page=3`；加密或损坏的 PDF 记为解析失败；文字太少的页面标记 `needs_ocr`。
- **HTML**：去掉导航、页眉页脚和侧栏，按 h1–h3 分节切块，locator 写成 `section=<标题路径>`；日期从页面里的“更新日”“掲載日”等字样抽取，抽不到就记为 `no_data_date`。

### 6.3 抓取监控（在 IVY-107 之上）
- 定时、开关、运行锁、运行记录和管理页面已由 IVY-107、610 提供，本版本只加提醒。
- 提醒规则：某来源连续 N 次抓取失败；解析失败率比过去 7 天的平均值高出阈值；超过预期频率仍没有成功抓取；短保留来源（JMA）出现时间缺口。提醒里写明失败类型（6.1）。
- 提醒显示在 `datumoj schedule status` 和管理页面上。

### 6.4 变化检测与报告
- 每次解析后，比较同一 doc_key 的新旧快照，生成 `ChangeEvent`。法令按修订、统计表按内容哈希、网页按正文差异比例（低于阈值不算修改）判断。
- `datumoj report weekly [--since]`：按来源分节输出 Markdown，每条带出处；同时列出这一周的抓取失败、提醒和 `needs_ocr` 统计。
- 工具层新增 `list_changes(since, sources)`，并通过 MCP 暴露。

### 6.5 IVY 遗留的检索缺口
- **关键词相关性门槛**（E 线）：向量一侧已有按模型取值的阈值（IVY-505、H5）；关键词一侧加上类似的判断（例如命中的查询词比例、BM25 分数下限），只剩低相关命中时判为 `zero_hits`。阈值在评测语料上校准，并写进 ADR。
- **e-Stat 统计表进入目录**（C 线）：e-Stat 解析器在产出观测值的同时，为每张表产出一条 `Dataset`（表题、调查名、统计期间、地区层级），这样 `search_catalog` 能找到它，`query_sql` 再取数值。
- **目录结果能还原**（D 线）：目录库保存 6.1 新增的快照引用，`search_catalog` 的出处带上 `snapshot_sha256` 和 `locator`。

### 6.6 存储适配层（为网络存储做准备）
- **一处配置**：现在 `cli.py`、`wiring.py`、`analysis/tools.py`、`core/rawstore.py` 各自读 `DATUMOJ_DATA_DIR`。收拢成一个存储配置，所有库（raw、manifest、chunk、目录、观测值、向量、报告）的位置都从它取。
- **`RawStore` 的 S3 兼容实现**：R2 提供 S3 兼容接口，实现放在独立的适配模块；用 IVY 已有的 `RawStoreSuite` 契约测试，在本机模拟的 S3 服务上跑，测试不连真实的 R2。凭证从 `.env` 或环境变量读，日志不出现凭证。
- **ADR**：manifest、目录、chunk 等 SQLite 库上网络存储的方式（迁到 D1、换成别的库，或本机运行、定期同步备份到 R2），以及 LanceDB / Parquet 直接读写对象存储的可行性。只出结论，不在本版本迁移。
- **2026-10-22 决定（ADR 0002）**：索引跟随数据上 R2，本机的库和索引可以按需从 R2 重建；同步频率按来源分别设置（有的来源要频繁抓取，有的只需周期性，周期长短各不相同）。实现另排任务，不在 103 里做。
- 本机实现继续是默认值，切换只改配置。

### 6.7 注册层描述导出
- `datumoj registry export` 读 `sources/*.yaml`，按 `schemas/registry/data-source.schema.json` 生成 `catalog/<source_id>.json`；`sources/*.yaml` 里没有的字段填 `unknown`，不编造。
- 生成的 JSON 提交进仓库，由 PR #5 的 `tests/validate_schemas.py` 和 CI 检查；再加一个测试，确认 `catalog/` 与 `sources/*.yaml` 一致（防止只改一边）。
- 在 `docs/interoperability.md` 补一段映射说明：`sources/*.yaml` 字段 ↔ 注册层字段，`Citation` ↔ 证据标准 §3.1 的证据链字段。

## 9. 风险

| 风险 | 应对 |
|---|---|
| 政策网页结构五花八门，正文抽取质量参差 | 每个种子站点至少一个样本进测试；抽取失败率按站点统计，进监控 |
| 网页抓取越界或违反利用规约 | 域名白名单、深度上限、robots.txt、单来源容量上限；H2 逐站核对规约 |
| 关键词门槛设得太严，漏掉真正相关的命中 | 在 IVY 的 60 题和本版新题上校准，Recall 不能低于门槛；校准过程写进 ADR |
| 这台机器休眠或关机，定时任务中断 | launchd 唤醒后补跑；监控提醒短保留来源的时间缺口；变化报告注明“本周哪些来源有缺口” |
| PDF 体积大、数量多，磁盘增长快 | 单文件和单来源都设容量上限；扫描件只记元数据；以后落到网络存储（6.6） |
| 存储适配层改动 IVY 的接线代码，引起回归 | 103 只收拢配置、不改各库的读写逻辑；合并后在主对话里跑一次全部测试 |
| R2 凭证泄露 | 测试只用模拟 S3；凭证只放 `.env` 或平台 Secrets，CI 的密钥扫描覆盖；日志不出现凭证（`SECURITY.md`） |
| 契约修订影响 IVY 已有代码 | 修订任务明确列出 `unprotect`；修订合并后，在主对话里跑一次全部测试 |
| 重做的任务丢失前几轮已确认的要求（IVY 中出现过） | 审查确认的要求写进任务文件的固定条目，不只写在打回理由里 |
