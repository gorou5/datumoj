# DATUMOJ 0.2（代号 TACHIBANA，橘）计划

> 草案 v0.2（2026-10-21）：按 IVY（0.1）的结果修订。总计划见 `docs/PLAN.md`，版本规则见其第 8 节。
> 任务编号 `DATUMOJ-TACHIBANA-<序号>`，号段沿用开发线：契约修订 001–009，A 线 1xx，B 线 2xx，C 线 3xx，D 线 4xx，E 线 5xx，F 线 6xx，G 线 7xx，集成 9xx。

## 0. 流程（本版本起）

1. **计划 PR（本文件）**：只含计划文件，由团队审核。**合并前提**：zenithli 团队已按 `docs/references/` 的规范提交 KKJ 的调研资料和样本（见第 5 节）。
2. **任务 PR**：计划合并后拆成任务文件（`docs/tasks/DATUMOJ-TACHIBANA-*.md`），单独提 PR；合并后才同步给调度器开工。
3. **代码走 PR**：TACHIBANA 期间的代码、测试、配置改动按批次各自提 PR，不再等版本完成后一次性推送。
4. **提交规则**：代码、文档、配置分开提交；不属于同一批次的改动不混在一起；计划文件只出现在计划和任务的 PR 里。

## 1. 一句话

把资料库从“能查法令、目录、统计、气象”扩到**采购公告和政策网页**，补上 IVY 留下的检索缺口，并让人**每周知道资料库里变了什么**。

## 2. 为什么做这些

IVY 完成后，链路已经打通，抓取也能按开关定时运行（IVY-107、610），但还有三类缺口：

- **覆盖面不够**：旧项目验收时答不出的问题，在 IVY 里也答不出，因为相关来源还没接进来。
  - “大阪市の AI スタートアップ支援策”：缺省厅和自治体的政策网页。IVY 验收（H6 第 7 题）时，检索只命中了含“大阪”字样的无关旧法令。
  - “近期大阪有哪些 IT 采购”：缺官公需情报门户 KKJ，以及公告附带的 PDF 规格书。
- **检索质量的已知缺口**（IVY 验收记录第 4 节）：
  - 关键词检索没有相关性门槛：问资料库里没有的东西时，常见词也会命中无关内容，缺口状态却判为 ok。
  - e-Stat 统计表只能用 SQL 查到，`search_docs` 和 `search_catalog` 都找不到。
  - 目录检索的结果还原不到它来自哪一次快照。
- **缺少运营视角**：抓取失败只在运行记录里，没有提醒；资料多了以后，人需要知道“这周变了什么”。

## 3. 目标（TACHIBANA 完成的标准）

1. **KKJ 采购公告入库**：按日期增量采集；附带的 go.jp / lg.jp 文本型 PDF 按页切块，能引用到页码；担当者的个人信息入库前脱敏。
2. **政策网页入库**：种子清单内的省厅和自治体页面，以及页面链接的 PDF 都能抓到并按节切块；SPA 外壳和空页面会被识别出来，不会当作成功。
3. **BODIK 入库**：复用 CKAN 采集器，再加上 DataStore 数据读取。
4. **抓取监控**：基于 IVY-107 的运行记录，连续失败、解析失败率突然升高、超过预期频率没有成功抓取时，`datumoj schedule status` 和管理页面（`datumoj admin`）给出提醒。
5. **每周变化报告**：每周在 `data/reports/` 生成一份 Markdown，按来源列出新增、修改、删除和失败，每条都带出处。
6. **IVY 遗留的检索缺口补上**：
   - 关键词检索有相关性门槛，资料库里没有的问题判为 `zero_hits`；
   - e-Stat 统计表作为数据集进入目录检索；
   - 目录检索的结果能还原到快照。
7. **评测**：新增 KKJ、政策网页、变化、脱敏四类题，以及覆盖第 6 条的题，共 30 题以上；和 IVY 的 60 题一起全部达标。
8. **真实问答验收**：在 Claude Code 里注册 MCP，亲手回答第 2 节的两个问题，回答带出处，不判断投标资格或中标结果。

## 4. 不做

- **OCR**：扫描件 PDF 只标记 `needs_ocr` 并统计数量，不识别。
- **登录后才能看的页面**、表单提交、需要执行 JavaScript 才能看到正文的页面（只识别为 SPA 外壳）。
- **全站爬取**：政策网页只抓种子清单和限定深度内的链接。
- **投标资格、中标结果、补助是否适用**等个案判断。
- **主动推送**（邮件、聊天通知）：变化报告只写到本地文件，提醒只在命令行和管理页面里显示。
- **定时与开关**：IVY-107、610 已完成，本版本不再重做。
- e-Stat API、国土数值信息、经济普查 2024、医疗开放数据、ABR 地址、气象厅平年值、国土地理院标高：放到 0.3 或之后。
- 欧美来源：0.3 以后。

## 6. 设计上的新增内容

### 6.1 契约修订（先做，由人审查）
- **`ChangeEvent`**：来源、doc_key、类型（新增 / 修改 / 删除 / 抓取失败 / 解析失败）、新旧快照的 sha256、发现时间、摘要。要能引用到快照。
- **`Redaction`**：脱敏记录，包括替换了哪类信息（姓名 / 电话 / 邮箱）、在哪个 locator、用的占位符。**原文不入库**，只保留“这里被替换过”的事实。
- **`Document.kind`**：`law`、`notice`、`html_page`、`pdf`、`dataset`、`bulletin`，检索时可以按类型过滤。
- **快照之间的父子关系**：公告或网页 → 附件 PDF，回答时可以说明“这份规格书附在哪份公告下”。
- **`Dataset` 记录来源快照**（IVY-603 提出的缺口）：加上 `snapshot_sha256` 和 `locator`，目录检索结果能用 `cite` 还原。
- 修订会影响 IVY 已有的代码，所以契约修订任务的 `unprotect` 要明确列出哪些已有测试允许改（调度器 A-004 规则）。

### 6.2 PDF 与 HTML
- **PDF**：用 pypdfium2 抽文本、pdfplumber 抽表格（表格可选）；每页一个 Chunk，locator 写成 `page=3`；加密或损坏的 PDF 记为解析失败；文字太少的页面标记 `needs_ocr`。
- **HTML**：去掉导航、页眉页脚和侧栏，按 h1–h3 分节切块，locator 写成 `section=<标题路径>`；日期从页面里的“更新日”“掲載日”等字样抽取，抽不到就记为 `no_data_date`。

### 6.3 抓取监控（在 IVY-107 之上）
- 定时、开关、运行锁、运行记录和管理页面已由 IVY-107、610 提供，本版本只加提醒。
- 提醒规则：某来源连续 N 次抓取失败；解析失败率比过去 7 天的平均值高出阈值；超过预期频率仍没有成功抓取；短保留来源（JMA）出现时间缺口。
- 提醒显示在 `datumoj schedule status` 和管理页面上。

### 6.4 变化检测与报告
- 每次解析后，比较同一 doc_key 的新旧快照，生成 `ChangeEvent`。法令按修订、统计表按内容哈希、网页按正文差异比例（低于阈值不算修改）判断。
- `datumoj report weekly [--since]`：按来源分节输出 Markdown，每条带出处；同时列出这一周的抓取失败、提醒和 `needs_ocr` 统计。
- 工具层新增 `list_changes(since, sources)` 和 `search_notices`（按机关、地区、类别、公告日、截止日过滤），并通过 MCP 暴露。

### 6.5 IVY 遗留的检索缺口
- **关键词相关性门槛**（E 线）：向量一侧已有按模型取值的阈值（IVY-505、H5）；关键词一侧加上类似的判断（例如命中的查询词比例、BM25 分数下限），只剩低相关命中时判为 `zero_hits`。阈值在评测语料上校准，并写进 ADR。
- **e-Stat 统计表进入目录**（C 线）：e-Stat 解析器在产出观测值的同时，为每张表产出一条 `Dataset`（表题、调查名、统计期间、地区层级），这样 `search_catalog` 能找到它，`query_sql` 再取数值。
- **目录结果能还原**（D 线）：目录库保存 6.1 新增的快照引用，`search_catalog` 的出处带上 `snapshot_sha256` 和 `locator`。

## 9. 风险

| 风险 | 应对 |
|---|---|
| KKJ 资料迟迟不到位 | 计划 PR 以资料到位为合并前提；如需提前开工，先做不依赖 KKJ 的 102、401、501、701、702 |
| 政策网页结构五花八门，正文抽取质量参差 | 每个种子站点至少一个样本进测试；抽取失败率按站点统计，进监控 |
| 网页抓取越界或违反利用规约 | 域名白名单、深度上限、robots.txt、单来源容量上限；H2 逐站核对规约 |
| KKJ 公告里的个人信息漏脱敏 | 脱敏规则覆盖姓名、电话、邮箱的常见写法；评测里放脱敏题；204 由人审查 |
| 关键词门槛设得太严，漏掉真正相关的命中 | 在 IVY 的 60 题和本版新题上校准，Recall 不能低于门槛；校准过程写进 ADR |
| 这台机器休眠或关机，定时任务中断 | launchd 唤醒后补跑；监控提醒短保留来源的时间缺口；变化报告注明“本周哪些来源有缺口” |
| PDF 体积大、数量多，磁盘增长快 | 单文件和单来源都设容量上限；扫描件只记元数据 |
| 契约修订影响 IVY 已有代码 | 修订任务明确列出 `unprotect`；修订合并后，在主对话里跑一次全部测试 |
| 重做的任务丢失前几轮已确认的要求（IVY 中出现过） | 审查确认的要求写进任务文件的固定条目，不只写在打回理由里 |

## 10. 和 IVY 的关系

- IVY（0.1）已完成并推送（tag `v0.1.0-ivy`）。TACHIBANA 在其之上开发，IVY 的 60 道评测题和 5 项门槛继续作为回归基线。
- IVY 的验收记录（`docs/acceptance/v0.1.0-ivy.md` 第 4 节）里的遗留问题，第 1–3 条并入本版本第 6.5 节；其余（全量法令、利用规约核对）不在本版本范围内。
