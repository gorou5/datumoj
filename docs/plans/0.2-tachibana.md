## 1. 一句话

把资料库从“能查法令、目录、统计”扩到**采购公告和政策网页**，并让它**每天自动增量更新、每周告诉人有什么变化**。

## 2. 为什么做这些

IVY 完成后，链路已经打通，但还有两类缺口：

- **覆盖面不够**：旧项目验收时答不出的问题，在 IVY 里也答不出，因为相关来源还没接进来。
  - “大阪市の AI スタートアップ支援策”：缺省厅和自治体的政策网页。
  - “近期大阪有哪些 IT 采购”：缺官公需情报门户 KKJ，以及公告附带的 PDF 规格书。
- **只能手动运行**：IVY 每次都要人跑 `make crawl`。气象厅这类只保留约 7 天的来源，中断就会丢历史；资料多了以后，人也需要知道“这周变了什么”。

## 3. 目标（TACHIBANA 完成的标准）

1. **KKJ 采购公告入库**：按日期增量采集；附带的 go.jp / lg.jp 文本型 PDF 按页切块，能引用到页码；担当者的个人信息入库前脱敏。
2. **政策网页入库**：种子清单内的省厅和自治体页面，以及页面链接的 PDF 都能抓到并按节切块；SPA 外壳和空页面会被识别出来，不会当作成功。
3. **BODIK 入库**：复用 CKAN 采集器，再加上 DataStore 数据读取。
4. **定时增量**：这台机器上的定时任务按来源配置的频率自动运行，休眠唤醒后会补跑，有防重入锁；抓取失败或解析失败率突然升高时，`datumoj status` 会给出提醒。
5. **每周变化报告**：每周在 `data/reports/` 生成一份 Markdown，按来源列出新增、修改、删除和失败，每条都带出处。
6. **评测**：新增 KKJ、政策网页、变化、脱敏四类题，共 25 题以上，和 IVY 的 60 题一起全部达标。
7. **真实问答验收**：在 Claude 里通过 MCP 回答上面两个旧项目答不出的问题，回答带出处，不判断投标资格或中标结果。

## 4. 不做

- **OCR**：扫描件 PDF 只标记 `needs_ocr` 并统计数量，不识别。
- **登录后才能看的页面**、表单提交、需要执行 JavaScript 才能看到正文的页面（只识别为 SPA 外壳）。
- **全站爬取**：政策网页只抓种子清单和限定深度内的链接。
- **投标资格、中标结果、补助是否适用**等个案判断。
- **主动推送**（邮件、聊天通知）：变化报告只写到本地文件。
- e-Stat API、国土数值信息、经济普查 2024、医疗开放数据、ABR 地址、气象厅平年值、国土地理院标高：放到 0.3 或之后。
- 欧美来源：0.3 以后。

## 6. 设计上的新增内容

### 6.1 契约修订（先做，由人审查）
- **`ChangeEvent`**：来源、doc_key、类型（新增 / 修改 / 删除 / 抓取失败 / 解析失败）、新旧快照的 sha256、发现时间、摘要。要能引用到快照。
- **`Redaction`**：脱敏记录，包括替换了哪类信息（姓名 / 电话 / 邮箱）、在哪个 locator、用的占位符。**原文不入库**，只保留“这里被替换过”的事实。
- **`Document.kind`**：`law`、`notice`、`html_page`、`pdf`、`dataset`、`bulletin`，检索时可以按类型过滤。
- **快照之间的父子关系**：公告或网页 → 附件 PDF，回答时可以说明“这份规格书附在哪份公告下”。
- 修订会影响 IVY 已有的代码，所以契约修订任务的 `unprotect` 要明确列出哪些已有测试允许改（调度器 A-004 规则）。

### 6.2 PDF 与 HTML
- **PDF**：用 pypdfium2 抽文本、pdfplumber 抽表格（表格可选）；每页一个 Chunk，locator 写成 `page=3`；加密或损坏的 PDF 记为解析失败；文字太少的页面标记 `needs_ocr`。
- **HTML**：去掉导航、页眉页脚和侧栏，按 h1–h3 分节切块，locator 写成 `section=<标题路径>`；日期从页面里的“更新日”“掲載日”等字样抽取，抽不到就记为 `no_data_date`。

### 6.3 定时与监控
- `datumoj schedule install|uninstall|show`：按 `sources/*.yaml` 里的 `schedule` 生成 launchd 配置；同一条命令也能输出 cron 行，以后换到 Linux 可用。
- 每次运行写一条运行记录，包括新增、未变、失败、用时；用文件锁防止重入。
- `datumoj status` 增加提醒：某来源连续 N 次抓取失败、解析失败率比过去 7 天的平均值高出阈值、超过预期频率仍没有成功抓取。

### 6.4 变化检测与报告
- 每次解析后，比较同一 doc_key 的新旧快照，生成 `ChangeEvent`。法令按修订、统计表按内容哈希、网页按正文差异比例（低于阈值不算修改）判断。
- `datumoj report weekly [--since]`：按来源分节输出 Markdown，每条带出处；同时列出这一周的抓取失败和 `needs_ocr` 统计。
- 工具层新增 `list_changes(since, sources)` 和 `search_notices`（按机关、地区、类别、公告日、截止日过滤），并通过 MCP 暴露。

## 9. 风险

| 风险 | 应对 |
|---|---|
| 政策网页结构五花八门，正文抽取质量参差 | 每个种子站点至少一个样本进测试；抽取失败率按站点统计，进监控 |
| 网页抓取越界或违反利用规约 | 域名白名单、深度上限、robots.txt、单来源容量上限；H2 逐站核对规约 |
| KKJ 公告里的个人信息漏脱敏 | 脱敏规则覆盖姓名、电话、邮箱的常见写法；评测里放脱敏题；审查 204 由人做 |
| 这台机器休眠或关机，定时任务中断 | launchd 唤醒后补跑；变化报告注明“本周哪些来源有缺口”；气象厅这类短保留来源的缺口单独提示 |
| PDF 体积大、数量多，磁盘增长快 | 单文件和单来源都设容量上限；只下载文本型 PDF 的原文件，扫描件只记元数据 |
| 契约修订影响 IVY 已有代码 | 修订任务明确列出 `unprotect`；修订合并后，在主对话里跑一次全部测试 |

## 10. 和 IVY 的关系

- TACHIBANA 的任务等 IVY 的契约二（002）和执行器（105）合并后再写进 `.orch/tasks/`。可以和 IVY 剩余的任务同时运行：调度器并发上限是 3，IVY 的依赖关系不受影响。
- 推送规则不变：IVY 完成后，连同 TACHIBANA 已完成的部分一起推送。
