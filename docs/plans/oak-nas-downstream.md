# OAK（柏）：NAS 下游副本

> 草案 v1（2026-11-11）。并行小版本之一，规则见 `docs/plans/parallel-versions.md`。任务编号 `DATUMOJ-OAK-<序号>`，分支 `feature/oak`。
> 背景：2026-10-30 定，数据先放 R2，由 GitHub Actions 写入；NAS 改为从 R2 取数据的下游副本（`docs/PLAN.md` 第 4.4 节）。NAS 部署说明另见 PR #53（ReadyNAS 自取 R2）。

## 1. 一句话

让 NAS 每天从 R2 增量拉取，保存一份校验过的只读副本；R2 上的旧数据被清理后，NAS 仍保留历史，研究时从 NAS 或 R2 读，不再依赖本机 `data/`。

## 2. 完成标准

1. **增量拉取命令**：只拉新增或变化的对象（按对象键和 ETag/校验和比较），不整代重拉；可中断、可续传；只用只读凭据。
2. **校验**：拉取后逐个核对校验和；按代次描述文件检查引用的对象都在；代次描述只记 raw 前缀，所以还要从该代次的 `manifest.sqlite` 取必需的 raw 引用逐个核对，已标记为允许缺失的（过期标记）不算失败；缺失就报告。
3. **保留**：NAS 端按配置保留历史代次（比 R2 的 72 小时长），并有自己的容量上限和告警。
4. **定时运行**：NAS 上每天运行一次，失败有通知；运行记录可查。
5. **读取**：本机工具能指向 NAS 副本恢复某一代次做研究（只读）。

## 3. 不做

- NAS 不往 R2 写，不参与租约，不发布代次。
- 不改 Actions 上的写入流程。
- NAS 的硬件、网络和系统配置不在代码范围内（PR #53 的部署说明负责）。

## 4. 拥有的目录

- 新文件 `src/datumoj/rikolto/mirror.py`（拉取与校验）、`deploy/nas/`；
- 只读用 `core/state.py` 已有的接口；需要新接口时只加不改，并在 `parallel-versions.md` 第 4 节登记（与 KATABAMI 交叉）。

## 7. 风险

| 风险 | 应对 |
| --- | --- |
| 拉取产生大量 R2 读请求或出口流量费用 | 只拉差异；按对象清单比较；记录每次拉取的请求数和字节数 |

| 只读 token 权限过大 | H1 只授权读和列，探测到写权限就拒绝运行 |
