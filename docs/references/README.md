# 参考资料（外部提供）

这个目录存放项目以外的团队提供的**调研资料和参考样本**：来源的接口说明、参数和上限、利用规约要点、踩过的坑、真实响应样本等。

- 这里的资料只供参考，**不是代码，也不直接被测试使用**。
- **本仓库是公开仓库（public）**，提交到这里的任何文件都等于对外发布。所以样本只在许可允许再分发时才提交，内部资料、未公开的调研结论不要放进来。
- 测试用的样本放在 `tests/fixtures/`，由各开发线负责人在录制样本（H1）时，从这里挑选需要的文件复制过去，并补上来源说明。

## 目录结构

每个来源一个目录，目录名用来源 ID（和 `sources/<id>.yaml` 一致）。跨来源的主题（例如许可汇总）用 `_` 开头：

```
docs/references/
├── README.md                  # 本文件
├── _licenses/                 # 跨来源的许可、利用规约汇总
├── jp-kkj/                    # 官公需情报门户
│   ├── README.md              # 必填：元信息（格式见下）
│   ├── notes.md               # 调研笔记：端点、参数、分页、上限、坑
│   ├── terms.md               # 利用规约要点（摘要 + 原文链接 + 核对日期，不转载全文）
│   └── samples/               # 可选：真实响应样本
│       ├── SAMPLES.md         # 每个文件的来源 URL（去掉 Key）、抓取时间、用途
│       ├── SHA256SUMS
│       └── ...
├── jp-egov-law/
├── jp-stat-dashboard/
├── jp-jma/
└── jp-gsi/                    # 国土地理院（标高等）
```

来源 ID 还没定的，先用 `jp-<简称>`，合并前由项目负责人确认。

## 每个来源目录的 README.md（必填）

```markdown
# <来源名>（<来源 ID>）

| 项目 | 内容 |
|---|---|
| 提供者 | <团队或个人> |
| 资料整理日期 | YYYY-MM-DD |
| 资料核对日期 | 最后一次对照官方页面确认的日期 |
| 官方入口 | <URL> |
| 需要 Key | 是 / 否（只写怎么申请，不写 Key 本身） |
| 许可 / 利用规约 | <名称和 URL>；可否再分发：可以 / 不可以 / 未核对 |
| 本资料的可信度 | 已用真实请求验证 / 仅读文档 / 推测 |
| 对应的 DATUMOJ 任务 | 例如 DATUMOJ-IVY-201（可空） |

## 内容清单
- notes.md：……
- samples/：……
```

## 提交方式：一个来源一个 PR

1. **分支**：从 `main` 拉分支。没有仓库写权限的从 fork 提交。分支名用 `ref/<来源 ID>`，例如 `ref/jp-kkj`。
2. **改动范围**：只改 `docs/references/<来源 ID>/` 这一个目录。其他目录（代码、`sources/`、`tests/`、计划文档）的改动请另提 issue 或 PR，不要夹在资料 PR 里。
3. **PR 标题**：`参考资料：<来源 ID> <主题>`，例如 `参考资料：jp-kkj 采集方法与样本`。
4. **PR 描述**：复制下面的检查清单并逐条勾选。
5. **审核和合并**：对应开发线的负责人审核内容，项目负责人合并。只有资料、不涉及代码的 PR 不走调度器。

### PR 检查清单

```markdown
- [ ] 只改了 docs/references/<来源 ID>/
- [ ] 目录里有 README.md，元信息填全
- [ ] 不含 API Key、Token、密码（包括 URL 参数和截图里的）
- [ ] 不含个人信息；KKJ 公告里的担当者姓名、电话、邮箱已替换成占位符
- [ ] 每个样本都在 SAMPLES.md 里写明来源 URL（去掉 Key）、抓取时间、用途，并列入 SHA256SUMS
- [ ] 单个文件 ≤ 5MB，本目录合计 ≤ 20MB；更大的文件不提交，在 notes.md 里写下载方法
- [ ] 样本的许可允许再分发；未核对或不允许的，不提交原文件，只写获取方法
- [ ] 利用规约只写摘要和原文链接，不整篇转载
```

## 格式要求

- 文档用 Markdown，中文或日文都可以。表格类资料优先用 CSV 或 Markdown 表格，尽量不提交 xlsx、pdf。
- 样本保持**原始字节**：不要重新编码、不要格式化 JSON、不要把 cp932 转成 UTF-8。编码问题本身就是要测试的内容。
- 写清楚**验证程度**：“真实请求验证过”“只读了文档”“推测”要分开写，和项目“不编数据”的原则一致。
- 同一来源的资料更新时，改原文件并更新“资料核对日期”，不要另建新目录。
