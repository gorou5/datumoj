### 1.2 e-Gov 目录（CKAN）

真实抓取暴露了两个问题，均已修复：

| 问题 | 修复 |
|---|---|
| 一个 PDF 资源超过单文件上限（当时 50MB），执行器却把它当成“来源总容量用尽”，停掉了整次采集（只抓到 1 页目录） | **DATUMOJ-IVY-106**：单文件超限只记失败、继续抓；累计超总容量或抓取器层截断才停止 |
| 增量把那次没走完的全量当成基准，于是只看“最近变化”列表就结束，200 个数据集的资源都没下载 | **DATUMOJ-IVY-403**：只有分页完整走到末尾的全量才能作为增量基准，否则退回全量 |

团队决定把 CKAN 的上限调整为**单文件 200MB、来源总额 10GB**（原为 50MB、2GB）。

另外，资源下载成功后目录状态一直停在“仅目录”（3,187 个资源全部如此），由 **DATUMOJ-IVY-609** 修复：成功下载的资源标为“已抓取正文”，状态只升不降，`index --rebuild` 时按 manifest 补核对。

## 2. H5：嵌入模型与向量阈值

详见 `docs/adr/0001-embedding.md`。要点：

- 本机 Ollama 拉取 **bge-m3**（1.2GB），在 60 题评测语料上用真实嵌入重建索引（83 份快照，约 2 分钟，0 失败）。
- 默认阈值 0.3 下**缺口门槛不达标**（0.875）：无关问题的向量最高分 0.471，被当成命中。相关检索题的向量最高分最低 0.685。取 **0.6**，阈值改为按模型取值（bge-m3 为 0.6，其他模型 0.3）。
- 在这份语料上混合检索的召回和纯关键词相同（0.962），MRR 略高；向量的价值要在更大的真实语料上再评估。
- 全量法令下的短查询耗时：目前真实语料只有 200 部法令（11,277 块），未测，留到全量抓取时。

## 4. 遗留问题（不阻塞 IVY 完成，转入后续版本）

1. **关键词检索缺少相关性门槛**：第 7 题这类资料库里没有答案的问题，只因为含常见词（大阪、市）就命中无关旧法令，缺口状态判为 ok。向量这一侧已有阈值（505、H5），关键词这一侧还没有。政策网页（jp-gov-web）在 0.2 版 TACHIBANA 接入。
2. **e-Stat 统计表在检索中不可见**：e-Stat 解析器只产出观测值，不产出可检索的数据集条目，`search_docs` 和 `search_catalog` 都找不到 e-Stat 表；数值用 SQL 能算对、出处能还原。
3. **目录结果还原不到快照**（603 提出的契约缺口）：已决定放到 TACHIBANA 的契约修订里做。
4. `version()` 的 `index_built_at` 为空，`freshness.as_of` 为空，信息不全。
5. 真实法令语料只有列表前 200 部（明治到昭和初期），现代法令（如个人信息保护法）未在真实语料里验证；全量抓取约 9,500 部、约 5 小时。
6. 各来源的利用规约尚未逐项核对，仍为 `internal_only`。
7. JMA 每小时定时轮询尚未安装（需要在本机添加 launchd 任务，另行确认）。

## 5. 在 Claude Code 里使用

在仓库根目录执行一次（需要已拉取 bge-m3，或设 `DATUMOJ_VECTORS=off` 用纯关键词）：

```bash
claude mcp add datumoj -- /opt/homebrew/bin/uv run --directory /Users/aaron/workspace/datumoj --frozen datumoj mcp
```

注册后在新会话里先调用 `version` 核对加载的是当前版本。
