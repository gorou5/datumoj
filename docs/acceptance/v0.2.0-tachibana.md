## 4. 发现的问题与处理

| 问题 | 处理 |
|---|---|
| 查询里有少于 3 个字的词时退回 LIKE 扫描，相关性门槛不生效；纯向量近邻也能让库外问题判 `ok` | 已修：MAPLE-144（LIKE 路径套门槛、纯向量命中不能单独支撑答案） |
| 单词查询只命中一个常见 trigram 就过门槛 | 已修：MAPLE-145（连续片段至少 4 个字、覆盖一半） |
| 覆盖率按词数算，生僻词和常见词同等对待；英文大阪问题丢了答案 | 已修：MAPLE-146（按 IDF 加权）；第 10 题重测改善 |
| 分词、英文的库外问题仍能靠常见词凑过门槛 | 未修，见第 5 节 |
| 变化流不含首次入库 | 待确认这是设计还是缺陷 |
| `cite` 引用的是快照中的条目号（`entry=N`），没有直接给出数据集 ID | 记录，不阻塞 |
| 真实语料上单条检索要 2–5 分钟 | 记录，另行排查 |

## 5. 已知局限

- **分词写法和英文写法的库外问题仍会返回无关结果。** 例如「月面基地 建設 補助金」「lunar base construction subsidy」：核心词（月面基地、lunar）在语料里一次都没出现，但「建設」「補助金」、base、subsidy 在真实语料里也不算常见，按 IDF 加权后覆盖率约 0.48 和 0.43，超过门槛 0.4。
- 曾尝试“语料里没出现的词占权重 1/3 以上就否决”（MAPLE-147），但评测里正常的库内关键词查询缺一个词时也会超过 1/3（例如 38.5%），会误伤库内题。要把 Q7 这两条和正常提问分开，阈值得放在 0.5 附近，余量只有 0.02，所以放弃了。之后再考虑别的做法（例如由回答方核对出处是否真的回答了问题）。
- 用户从 MCP 客户端提问时，回答方可以从返回的片段看出它和问题无关；这条局限影响的是“工具直接判库外”这一层。
