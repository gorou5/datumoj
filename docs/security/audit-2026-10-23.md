## 三、tel Worker（tel/src/**）

已查无发现：SQL 注入（全部查询为 D1 prepared statement + `.bind()`，号码入参先经路由正则/normalize 校验）；服务端 XSS（全部插值经 `esc()`）；客户端 XSS（评论等用户可控字符串一律 `textContent` 渲染）；路径穿越（Worker 无文件系统面）；`wrangler.toml` 无明文凭证。

发现 5 项 Low，**已全部随 tel/seo-watch 修复并部署**（commit d8addc4，Worker 版本 59024e9c）：

1. `/view` 计数接口无来源校验，任意第三方页面可借访客浏览器跨站 POST 刷高公开计数 → 已加 Origin 校验（外站来源 403，不计數；无 Origin 的运维调用照常），线上实测 403 生效。
2. 评论限流 SELECT 后 INSERT 的 TOCTOU 竞态，并发可绕过 5 条/小时 → 已改为单条原子 `INSERT … SELECT … WHERE count < 5`（SQL 语义已按 0005 表结构在 sqlite3 实测）。
3. IP 哈希盐为写死在公开仓库的常量，IPv4 哈希可离线字典反推 → 代码已支持 `IP_HASH_SECRET` Worker secret 作盐（未设置时回退旧盐保证部署不中断）；**待办（需 owner 操作）：执行 `wrangler secret put IP_HASH_SECRET` 后此项才算闭环**。
4. `layout()` 的 JSON-LD 未做 `</` 转义（与 hero 载荷的处理不一致；当前字段均来自官方种子数据，不可利用）→ 已对齐转义，本地用 `</script>` 载荷实测。
5. DB 中的来源 URL 进 href 只做 HTML 转义、未校验 scheme（`javascript:`/`data:` 理论可点穿；当前值均为逐条核验过的官方 URL）→ 已加 `extLink()` 只允许 http(s) 成链，其余降级为纯文本，三处调用点（政府号码、第三方标示、/gov 页）全覆盖，本地实测。
6. （健壮性）`decodeURIComponent` 在 try 之外，畸形 %-编码会抛未捕获 500 → 已加守卫回退未解码路径，线上实测返回站内 404。

提示（非缺陷）：HTML 响应未设 CSP 等安全响应头——站内内联脚本多，上 CSP 需 nonce 化改造，列入长期硬化清单；评论落库即公开（visible），内容安全依赖 ≤10 字＋违禁词表，属已知运营取舍。

## 四、Python 侧（src/datumoj/**、bin/、tel/scripts/**）

已查无发现：无 `shell=True`/`os.system`/`eval`/`exec`/`pickle` 加载/不安全 `yaml.load`/`verify=False`；唯二 subprocess 均为 argv 数组且参数受控。凭证处理有主动防泄漏设计（`redact_url()`、httpx 日志过滤、registry 字段脱敏）；唯一抓取栈 PoliteHttpFetcher 有 allowed_hosts 白名单 + 私网/回环 IP 双查 + 重定向逐跳重验，不附加任何 Authorization。tel/scripts 只读本地文件生成 SQL，不发网络请求。admin 管理页全量 `html.escape` + CSRF 令牌 + 只绑 127.0.0.1，在其部署模型内可接受（勿改绑 0.0.0.0 或经隧道暴露）。

设计提示（非漏洞）：MCP 服务按环境变量动态 import 工厂函数（本机 stdio 模型内不构成边界跨越，勿改造成网络监听形态沿用此机制）；PoliteHttpFetcher 的 DNS 检查-使用存在理论 rebinding 窗口（目标域已收窄到政府站点，实际风险很低）；`bin/orch` 写死个人机器路径（卫生问题，非安全问题）。
